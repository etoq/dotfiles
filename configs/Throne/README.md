# Throne на этой рабочей станции

Используется Throne 1.3.2 и его встроенный ThroneCore. Режим: TUN, system stack,
auto redirect. Сохраняется маршрут **Bypass Russia**: российские ресурсы и
локальные адреса напрямую, остальные через выбранный профиль.

`settings.json` — перечень настроенных параметров, а не файл для прямого импорта
в GUI. Личные профили, подписки, ключи и базы SQLite в dotfiles не копируются.
При переносе сначала импортировать личную резервную копию через Throne, затем
проверить эти параметры в настройках установленной версии.

- Последний профиль запускается автоматически; окно при входе скрыто в трей.
- Служба `throne.service` запускается из Awesome, bspwm и XDG autostart.
  Повторные вызовы запуска идемпотентны. При аварийном завершении GUI служба
  перезапускается через 5 секунд, максимум 3 запуска за 120 секунд.
  Обычный выход через меню намеренно не перезапускает программу.
- Подписки и удалённые маршруты обновляются раз в сутки через прокси.
- Включён обход прямых IP-маршрутов на уровне TUN и учёт `/etc/hosts` в DNS.
- Удалённый DNS: `https://8.8.8.8/dns-query` через прокси; прямой DNS:
  `localhost` (системные резолверы). Поэтому DNS прямых маршрутов может
  обращаться к системному резолверу; схема не является полным запретом DNS вне туннеля.
- Mixed HTTP/SOCKS: `127.0.0.1:2080`. Административные API выключены.
  Из гостевой VM этот loopback-адрес не ведёт на хост. Для обычного NAT
  оставить браузер гостя без ручного прокси. Изолированная сеть `debian_RE`
  сохраняется изолированной.
- TLS-проверка сертификатов включена. IPv6 TUN и FakeIP выключены;
  IPv6-маршрута по умолчанию на момент настройки нет. При добавлении IPv6
  проверить маршрутизацию повторно.
- Файловый журнал: warning; история статистики: 30 дней.
  Каталог профилей закрыт от других пользователей (`0700`), базы — `0600`.

Управление:

```sh
systemctl --user status throne.service
systemctl --user restart throne.service
systemctl --user stop throne.service
throne # открыть окно уже запущенного клиента
```

Закрытие окна в трей сохраняет соединение. Для отключения выбрать остановку
профиля в GUI или остановить службу. Автозапуск после следующего входа останется.
