# Перенос Linux RE и ConceptLoom после переустановки

В Git хранится конфигурация: собственная версия ConceptLoom 2.0, проектные инструкции, шаблон профиля, установщик и проверка восстановления. Файлы `English_For_Linux_RE.md`, `Linux_Malware_Roadmap.md`, `Learning_System.md`, учебный прогресс и личный vault сюда не публикуются.

## Если есть полный личный комплект

Сохрани `concept-loom-recovery-*.tar.gz` и соседний `.sha256` вне стираемого диска. После установки Arch распакуй архив обычным пользователем:

```bash
sha256sum -c concept-loom-recovery-YYYYMMDDTHHMMSSZ.tar.gz.sha256
tar -xzf concept-loom-recovery-YYYYMMDDTHHMMSSZ.tar.gz
cd concept-loom-recovery
bash restore.sh
```

Комплект содержит код, личные данные и всё необходимое для установки без загрузки исходников с GitHub. Нужны установленные Node.js 20+ и Python 3.11+; на Arch это пакеты `nodejs`, `npm`, `python`. Установи также Codex CLI и Obsidian. Авторизацию Codex выполняют заново в своём аккаунте; ключи и сессии авторизации в комплект не включаются.

По умолчанию используются домашняя папка текущего пользователя и пути:

```text
~/Tools/ConceptLoom
~/learning/linux-re
~/Documents/obsidian
~/.local/bin/linux-re
```

Другое имя пользователя и пробелы в путях поддерживаются. Для своих каталогов:

```bash
bash restore.sh --workspace /new/project --vault /new/obsidian --tools /new/Tools/ConceptLoom
```

После установки запусти `~/.local/bin/linux-re`, при необходимости войди в Codex и открой восстановленный каталог как vault в Obsidian.

## Установка только из GitHub

```bash
git clone https://github.com/etoq/dotfiles.git ~/dotfiles
cd ~/dotfiles
bash install.sh --learning
bash install.sh --learning --apply
```

Первый запуск показывает план, второй применяет конфигурацию. Родмапы и прогресс GitHub не содержит: восстанови их из личного комплекта. Если он уже распакован, можно передать его внутренний архив данных:

```bash
bash install.sh --learning --data-backup /path/concept-loom-recovery/private-data.tar.gz --apply
```

Без личного архива настраивается только инфраструктура. Пустая история и новые отметки освоения не выдумываются; запуск обучения сообщает о недостающих файлах.

## Сделать новую личную копию

```bash
python3 scripts/maintenance/backup-learning.py
```

По умолчанию комплект создаётся в `.learning-private/`, исключённой из Git. Можно указать внешний диск:

```bash
python3 scripts/maintenance/backup-learning.py --output /path/to/external/concept-loom-recovery.tar.gz
```

В комплект входят реальный текущий код MCP, настройки, инструкции, исходные материалы, прогресс и vault Obsidian с вложениями и настройками. Корзина, Git, временные блокировки и кэши исключены. Диск Debian VM, SSH и аккаунты сохраняются отдельной системной копией. Во время снимка состояния используется та же блокировка ОС, что у MCP; журнал проверяется перед упаковкой.

Архив содержит личные данные и родмапы. Он не предназначен для GitHub. Локальный файл на стираемом диске сам по себе переустановку не переживёт.

## Как переносится история

Исторические события и их хеши остаются неизменными. Пути в активном профиле пересчитываются, ссылки `notes/` создаются заново. Смена пути блокнота добавляется отдельным служебным событием, сохраняя ответы, помощь, маршрут и следующий шаг. Это увеличивает ревизию, но не добавляет учебную попытку.

Установщик проверяет хеши, не извлекает опасные ссылки или пути из архива и не затирает существующую историю. Повтор успешного восстановления не откатывает более поздний прогресс. Для конфликтующих файлов выбирают пустой каталог, а не принудительную замену.

Регистрация меняет только `mcp_servers.concept-loom` в конфигурации Codex, сохраняя другие настройки и резервную копию. Рабочий каталог задаёт launcher; глобальная регистрация не привязывается к одной учебной сессии. Формат регистрации сверяется с [официальной документацией OpenAI](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Проверка после восстановления:

```bash
node ~/Tools/ConceptLoom/scripts/doctor.mjs --workspace ~/learning/linux-re --session linux-re
```

Для продолжения в Codex загружается сохранённый следующий шаг. Состояние VM и временные файлы проверяются с учеником; восстановление конфигурации не означает, что лаборатория уже запущена.

Шаблон автоматической проверки GitHub Actions: `learning/learning-portability.workflow.yml`. Для включения скопируй его в `.github/workflows/learning-portability.yml` с правом управления workflows в GitHub. Локальные проверки доступны сразу.
