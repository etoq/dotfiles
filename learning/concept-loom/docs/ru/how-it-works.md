# Как работает ConceptLoom

ConceptLoom protocol: 2. Версия 2.0.0, формат состояния 3.

Сервер помогает сохранять проверяемые учебные записи: задание, ответ, условия, помощь, наблюдение, оценку наставника и точное продолжение. Он не запускает лабораторные команды и не превращает мнение модели в установленный факт.

## Продолжение занятия

Загрузи явную сессию через `loom_load_learning_state`, проверь `loom_status`, текущую сводку и `loom_list_due_reviews`. Затем `loom_begin_lesson` создаёт отдельный идентификатор занятия с сохранённой точки. Тема сохраняет свой постоянный `sessionId`. Новый курс или диагностику при возобновлении начинать не нужно.

Профиль Linux RE задаёт русский язык, Arch как хост, Debian VM как лабораторию, исполнение команд учеником, изоляцию других проектов и существующие пути Obsidian. Сведения профиля — настройки и правила проекта; это не результат автоматической проверки сети VM. `materials/` остаётся исходным снимком переноса.

## Проверки знаний

`loom_frame_checkpoint` получает публичное задание и закрытые ключи/критерии. До ответа показывается только публичная карточка. Она содержит стабильный ID задачи, формат, версию критериев, необязательный вариант и согласованные условия. Карточка живёт в памяти до шести часов и исчезает при перезапуске.

Доступны `choice`, `free-recall`, `prediction`, `debugging`, `transfer`, `verification`. Это характеристики проверяемого действия, не обязательная лестница и не общий балл.

Сразу после ответа `loom_assess_checkpoint` получает точный текст и следующий шаг. Для открытого ответа нужно передать `criterionResults` для каждого ID из `criterionIds`. У результата `pass` есть `evidenceQuote`, буквально присутствующая в ответе или предоставленном наблюдении. Все критерии должны иметь `pass` для вердикта `accurate`. Согласованность цитаты проверяет код; смысловую оценку по-прежнему даёт наставник.

Помощь указывается явно:

- `unknown`: не известно, какая помощь была;
- `none`: заявлена работа без подсказки;
- `hint`, `explanation`, `solution`: подсказка, объяснение или готовое решение.

Пропущенный `hintUsed` больше не означает самостоятельность. Старое явное `hintUsed=false` соответствует `none`, `true` — `hint`. Разрешённый справочник записывается отдельно и не становится подсказкой автоматически.

Наблюдения разделяются на `prediction`, `terminal-output`, `learner-explanation`, `coach-observation`. Заранее согласованные условия задания и фактически заявленные условия хранятся отдельно. Исходный текст, пробелы и вывод сохраняются; уверенность записывается только если ученик её сообщил. `confidenceSignal` — повод для обсуждения, а не измерение калибровки по одному ответу.

Закрытые ответы и критерии не записываются в постоянный журнал. Один верный выбор не добавляет глобальную отметку освоения. Исторические флаги сохраняются с прежним происхождением. Понятия имеют стабильные ID; `loom_rename_concept` меняет название без разрыва истории.

## Сохранение и повтор после сбоя

После каждого ответа запись предшествует следующему объяснению. Для обычного ответа используй `learnerResponse` или наблюдения в сохранении состояния; для проверки — её оценку. Не нужно заполнять дополнительную анкету ученику.

Сохранять можно только изменённые поля и `nextStep`: пропущенное сохраняется. `loom_patch_learning_state` требует загруженную `expectedRevision` и устойчивый `operationId`. Частичный `evidenceUpdates` сохраняет остальные записи. Полная замена `evidence` требует явных `replaceEvidence=true`, причины и ревизии; историю попыток через patch затирать нельзя.

Для повторения операции после неизвестного исхода используй тот же `operationId` и тот же ввод. Проверка автоматически получает устойчивый ключ из карточки. Даже после перезапуска сервера повтор уже сохранённой оценки вернёт квитанцию без новой попытки. Операцию можно проверить через `loom_status` с её ID. Новый ответ ученика — новая операция.

Ответ записи по умолчанию краткий; полное состояние доступно через загрузку или `includeState=true`. В `commitInfo` отдельно показаны фиксация события и ошибки представлений. Если событие сохранено, не оценивай ответ заново ради исправления Markdown: используй `loom_sync_learning_records`.

## Согласование и повторения

`loom_approve_route` связывает версию маршрута с реальной цитатой согласия и ссылкой на сообщение. Изменение маршрута или зависимостей делает согласование прежней версии неприменимым. Профиль проекта может запрещать проверки до нового согласия.

При переносе существующего проекта `legacy-context` сохраняет прежний контекст маршрута. Это не новое согласие и не новая проверка знаний. Следующая точка продолжения и старые свидетельства сохраняются.

Интервалы 1, 3, 7, 14 и 30 дней и минимальная пауза 24 часа — практическая настройка профиля. Рост требует самостоятельного результата, назначенного срока, достаточной реальной паузы и другого занятия. Пересечение срока между двумя быстрыми ответами не является отложенным воспроизведением. Список повторений не обязывает проходить все старые записи заново.

## Файлы и восстановление

```text
.concept-loom/project.json          правила и разрешённые пути проекта
.concept-loom/events/linux-re.jsonl история от явного исторического baseline
.concept-loom/sessions/linux-re.json восстанавливаемый снимок
.concept-loom/backups/              проверяемые предыдущие снимки
progress/linux-re-notebook.md       читаемый журнал
notes/active/Current_Stage.md        краткий управляемый блок и прежняя история
```

Событие сначала записывается с проверяемой цепочкой хешей, затем обновляются снимок, блокнот и сводка. Блокировка ОС защищает разные процессы и снимается после аварии. Нужны Node.js 20+ и Python 3.10+; сторонние runtime-пакеты не нужны.

Повреждённый снимок восстанавливается из проверенного журнала. Неизвестная будущая версия не перезаписывается. Незавершённый хвост журнала сохраняется отдельно перед исправлением; повреждение внутри цепочки требует разбора и блокирует запись только этой сессии. Старый backup не подменяет новые данные автоматически.

В настроенном проекте Markdown формируется автоматически из событий, без повторных ручных записей. Текущая сводка хранит ревизию, следующий шаг и сохранённую историческую часть; её обновление не переписывает обычные концептуальные заметки. Для внешнего файла нужен точный разрешённый реальный путь, а не весь vault. Ошибка доступа возвращается с путём; права не обходятся.

## Диагностика и обновление

`loom_status` показывает активную версию, проект и продолжение. `loom_doctor` дополнительно проверяет состояние, журнал, backup, Python и согласованность файлов/инструкций. Они не продвигают учебный прогресс.

```bash
node scripts/doctor.mjs --workspace /path/to/project --session linux-re
node scripts/migrate.mjs --workspace /path/to/project --session linux-re
node scripts/migrate.mjs --workspace /path/to/project --session linux-re --apply
node scripts/recover.mjs --workspace /path/to/project --session linux-re
```

Миграция и восстановление без `--apply` показывают план. Перед миграцией сохраняется копия данных и останавливаются старые записывающие MCP-процессы проекта. Подключение stdio остаётся прежним; клиенту нужен перезапуск для новых инструментов. Формат 3 нельзя использовать со старым сервером версии 1.
