# INCY 2.6.4 · iPhone

Подготовлено 21.10.2026. Политика как у Throne: российские домены/IP и локальная
сеть напрямую, остальные назначения через выбранный сервер. Это профиль
маршрутизации, а не подписка и не системный `.mobileconfig`.
Личные серверы, пароли и ссылки подписки сюда не включены.

## Импорт

Готовая копия: `~/Downloads/INCY-Black-Tiffany/`.

1. Свою подписку/сервер сначала добавить в INCY обычным способом.
2. Открыть `import-routing.txt`, скопировать **всю строку** и в INCY выбрать
   добавление из буфера обмена. Схема `incy://routing/onadd/BASE64` официальная:
   она импортирует и активирует профиль. Можно также открыть кнопку в
   `Открыть-на-iPhone.html` на iPhone; если просмотрщик файлов не разрешит переход,
   использовать буфер обмена.
3. Проверить, что выбран **Black Tiffany - RU direct**, маршрутизация включена,
   загрузка обоих геофайлов завершилась без красного восклицательного знака.
4. Переподключить VPN. Импортировать маршрут вместо существующего профиля сервера
   как полный Xray-конфиг **не нужно**.

JSON для просмотра/редактирования: `routing-ru-direct.json`. Сама возможность
открыть произвольный JSON из приложения «Файлы» зависит от интерфейса сборки;
основной способ выше использует документированный импорт ссылки.
`import-qr.png` содержит ту же ссылку; сканировать с экрана компьютера.

## Что задать в настройках приложения

Для всех глобальных переключателей не найден документированный универсальный
файл импорта. Следующие пункты выставляются вручную. Названия могут отличаться
в русской локализации; если пункта нет, ничего похожего наугад не менять.

| Пункт | Значение |
| --- | --- |
| Routing / Профили маршрутизации | Вкл.; Black Tiffany - RU direct |
| Bypass private IPs / Обход LAN | Вкл., если есть отдельный переключатель |
| VPN DNS | Публичный пресет Cloudflare / 1.1.1.1, **не Internal** |
| FakeDNS | Выкл. — уже задано в профиле |
| Sniffing / Определение домена | Вкл., если доступно; без расшифровки TLS |
| Предпочтительный IP | Auto; IPv6 целиком на iPhone не отключать |
| MTU, число соединений, таймауты | Штатные значения |
| Mux / Multiplexing | Выкл. для начального профиля |
| Фрагментация и шумы | Выкл.; включать только при конкретном сбое соединения |
| Автообновление подписки | Раз в 24 часа, если провайдер разрешает |
| Геофайлы → интервал обновления | 7 дней, если редактор предлагает этот пункт |
| Автоподключение / On Demand | Вкл. для постоянного использования, если доступно |
| Автоподключение после разблокировки | Вкл., если доступно |
| Журнал | Warning, обычное подробное логирование выключено |
| Оформление | Тёмное; cyan/teal-акцент при наличии выбора |

В iOS используется системный VPN-туннель: выбирать Linux System Proxy вместо TUN
здесь не нужно. Kill Switch — отдельный выбор: включить, если при обрыве VPN
нужно блокировать доступ, а не продолжать работу напрямую. После включения
отдельно проверить доступ к LAN. Точные исключения определяет Apple VPN extension;
один JSON маршрутизации не даёт гарантии отсутствия утечек при отключённом VPN.

## Что делает файл

- `GlobalProxy: "true"` — прокси по умолчанию **при подключённом VPN**.
- Direct: `geosite:category-ru`, домены `.ru/.su/.рф`, `geoip:ru`, private IPv4/IPv6,
  localhost и локальные домены. Российский IP может направить напрямую и
  иностранный домен, размещённый в России — это следствие правила по стране IP.
- Remote DNS: Google DoH через прокси. Domestic DNS: базовый Яндекс DNS
  `77.88.8.8` напрямую по UDP. DNS прямых ресурсов виден прямому резолверу;
  это соответствует выбранному разделению, а не режиму «весь DNS только в VPN».
- FakeDNS выключен; `useChunkFiles: true` уменьшает геофайлы до используемых тегов
  на мобильном клиенте. Если переключать VPN DNS на Internal, HEV может выдавать
  виртуальные адреса независимо от `FakeDNS` — поэтому выбран публичный пресет.
- Реклама и приложения дополнительно не блокируются; смена сервера не зашита.
- Имена тегов проверены в скачанных GeoIP/GeoSite Loyalsoldier:
  **RU/PRIVATE** и **CATEGORY-RU/PRIVATE**. `geosite:ru` в этом наборе отсутствует.

Локальная сеть по IP работает по правилам; обнаружение устройств через Bonjour/
mDNS зависит также от разрешений iOS «Локальная сеть». Если iOS запросит такое
разрешение при обращении к домашним устройствам, его нужно разрешить.

## Проверить на телефоне

С включённым VPN открыть российский сайт, иностранный сайт с проверкой внешнего
IP и домашний роутер по его локальному адресу. Где клиент показывает журнал
маршрутов, проверить direct/proxy для этих соединений. Затем повторить проверку
через мобильную сеть и после блокировки/разблокировки iPhone. Открытие сайта само
по себе не доказывает выбранный маршрут. Личный VPN-сервер должен быть доступен
и подписка должна разрешать ещё одно устройство.

В App Store подтверждена версия 2.6.4, минимальная система iOS 15.0. Отдельного
формата для iOS 26.6.1/27.0.1 не заявлено; совместимость именно этих сборок и
реальную работу VPN здесь не проверяли. После обновления iOS используется тот
же профиль; проверку выше повторить, прежде чем считать переход завершённым.
