# Исправления аудита

`verify-kernel-stack` проверяет только ядра из списков установленных пакетов
pacman. Код 0 — проверка пройдена, 1 — обнаружена ошибка, 2 — часть проверки
недоступна текущему пользователю (например, initramfs требует sudo).

`wispr-a11y-guard` проверяет состояние процессов и очередь AT-SPI, не читая
текст диктовки и буфер обмена. При двух последовательных наблюдениях
переполненной очереди либо отсутствии помощника в течение 90 секунд
восстанавливает Flow в фоне. Не чаще одного раза в 30 минут, максимум
два раза в час. Закрытый пользователем Flow не запускает.

Thinkfan сохраняет обычный и тихий профили. Кратковременные ошибки датчиков
ThinkPad допускают три повторные попытки; служба имеет ограниченный перезапуск
при ошибке. При постоянном сбое требуется диагностика, а не игнорирование GPU.

Постоянное правило SSH ограничено IPv4-подсетью `192.168.0.0/24` через
`enp0s31f6`. Другой удалённый маршрут нужно согласовать перед применением.

Локальный план `finish-audit-eight.py` хранится вне Git, сверяет хеши
исходных файлов, создаёт root-only backup и печатает команду отката.
Он не обновляет NVIDIA и не перезапускает сеть. Включение audit=1 на этом компьютере вызвало audit_log_subj_ctx, переполнение
очереди и отказ auditd. Рабочая политика — audit=0 и отключённый auditd;
AppArmor остаётся включённым. Для восстановления предназначен
`scripts/maintenance/recover-audit-boot.py --apply` с sudo.

Wispr запускается службой `systemctl --user start wispr-flow.service`
из Awesome/bspwm и XDG autostart, скрытым в фоне. При аварийном завершении
служба повторяет запуск через 10 секунд, максимум 3 запуска за 5 минут.
Обычный выход не вызывает повторного запуска. Guard перезапускает управляемый
Flow через systemd, который очищает старую группу процессов перед запуском.
