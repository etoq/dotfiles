# Уход от рабочего места: Otter → ol

`ol` отправляет приложениям обычное закрытие окна, а работающим ВМ из
`qemu:///system` — штатное выключение гостя через guest agent / ACPI.
Запросы выключения всех ВМ отправляются сразу; ожидание — до 90 секунд.
Если гость не отвечает, ВМ остаётся включённой и появляется предупреждение.
Принудительного выключения нет.

Остаются Throne, Flameshot, udiskie, EasyEffects, Wispr Flow со своими
помощниками и AyuGram. Если AyuGram отсутствует, команда запускает его.
Оконный менеджер, панель, звук, сеть, автомонтирование, таймер блокировки,
резервирование и прочие системные службы не останавливаются.

Редактор может запросить сохранение, терминал — подтверждение закрытия,
а приложение — свернуться в трей вместо выхода. Такие случаи не обходятся
сигналами завершения. Команда не нажимает «Не сохранять» и не закрывает
появившиеся диалоги повторно. Проверьте уведомление перед уходом.
Discord и другие приложения, остающиеся в трее, могут потребовать обычного
«Выход» в своём меню; работающий фоновый процесс отмечается в отчёте.
Произвольные фоновые задания из терминала отдельно не завершаются.

Экран не блокируется немедленно, сон не вызывается. После завершения
воспроизведения видео действует существующая автоблокировка с выключением
экрана через 10 минут без ввода. AyuGram продолжает получать сообщения.

Безопасный просмотр плана, без закрытия приложений и выключения ВМ:

```sh
~/.local/bin/workstation-away --dry-run
```

Применять удобнее из Otter: `ol`. Его `otter-run` отделяет команду от
терминала, поэтому ожидание выключения ВМ продолжается после закрытия окон.
Для запуска из терминала без его закрытия вместе с командой:

```sh
~/.local/bin/otter-run --module ol
```

Отчёт последнего запуска:
`~/.local/state/workstation-away/last-run.json`.
Журнал запуска: `~/.local/state/otter-tools/launches/ol.log`.
Повторный запуск во время работы предыдущего ничего не меняет.

Проверки: изолированный Xvfb проверяет настоящее сообщение WM_DELETE_WINDOW,
пропуск защищённых окон и отсутствие принудительного закрытия окна без
поддержки протокола. Отдельно проверяются команда выключения ВМ, защита
дочерних процессов Wispr и отсутствие повторного закрытия диалога сохранения.
Живые приложения пользователя тестами не закрываются.
