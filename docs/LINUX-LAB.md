# Linux/ELF лаборатория: проверка 18 октября 2026

## Фактическая конфигурация

Основной гость — debian_RE, Debian 13.7, 4 vCPU/8 GiB RAM. В момент проверки уже был запущен пользователем; агент его не запускал/не перезапускал. Диск около 75 GiB, в госте занято 4.7 GiB. Общих каталогов и USB-проброса в XML нет. Guest agent доступен; аудит выполнен его guest-exec командами чтения. Сохранён существующий внутренний снимок 00_clean_tools_ssh, он не откатывался и не заменялся. Название снимка не является доказательством отсутствия образцов в госте.

## Изоляция и SSH

Единственный интерфейс — isolated/virbr1, IP на момент проверки 10.10.10.39. В госте нет default route. Пробные TCP-подключения гостя к хосту на 22/3427 не прошли, к 1.1.1.1:443 — нет маршрута. Это проверка указанных путей, не доказательство всей модели изоляции.

Первый вариант строгого input drop для virbr1 также блокировал ответы на SSH с хоста к гостю. Подготовлена поправка: iifname virbr1 ct state established,related accept перед блокировкой остальных пакетов virbr1. Новые соединения гостя к хосту и forward virbr1 остаются запрещены. Только подготовленная конфигурация в dotfiles уже содержит правило; применение к рабочей машине требует sudo ~/.local/bin/finish-lab-ssh-fix. Скрипт проверяет исходный SHA256, сохраняет backup, валидирует nft и вставляет одно правило без рестарта служб.

Проверка на двух связанных veth в отдельном user/network namespace воспроизвела старую блокировку SSH, успешный SSH-подобный TCP round-trip с новой политикой и блокировку нового соединения из гостя к хосту. Доступ к настоящей VM нужно повторно проверить после root-применения. Исходные правила сохраняются в /var/backups/lab-ssh-replies-*.

## Что уже есть внутри

- GDB 16.3: отладка.
- GCC: компиляция собственных учебных программ.
- binutils (readelf, objdump, strings, nm): ELF, секции, дизассемблирование, строки, символы.
- Python 3.13: скрипты анализа.
- file, ss, lsof, jq, Git, wget.
- SSH и QEMU guest agent активны; отказавших системных units нет.

## Чего нет — ничего не устанавливалось

- strace: наблюдение за системными вызовами.
- ltrace: вызовы динамических библиотек.
- make: сборка учебных проектов.
- checksec: сводка защит ELF.
- YARA: правила и поиск сигнатур.

На момент проверки apt-кэш знает только DVD-индексы; make есть на DVD, strace не имеет кандидата, ltrace/checksec/yara в выводе policy не представлены. Нельзя обещать их установку простым apt install без подготовки источников. Интернет для гостя не включался, репозитории не менялись. Инструменты и образцы не скачивались, образцы не запускались.

Следующий отдельный шаг после SSH — выбрать минимальный комплект для гостя и подготовить контролируемую установку, сохранив обычный режим анализа без внешнего доступа. Новый рабочий снимок создавать после установки и проверки, при выключенном госте; текущую работающую VM и пользовательские сеансы ради этого автоматически не останавливать.

## Разделение работы

Сохранять образцы и логи внутри гостя; экспортировать отчёты явным действием. Не включать общие папки, clipboard, USB или обычный NAT автоматически ради удобства. Rootkit/модуль ядра исследуется в госте с последующим откатом заранее подготовленного снимка, а не загрузкой в ядро Arch.

Диски VM не входят в текущий облачный backup пользовательских папок. Внутренний снимок также находится на том же диске и не является внешней резервной копией.
