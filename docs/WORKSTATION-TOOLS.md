# Восемь инструментов для системы, файлов и анализа

Все доступны из Otter. Меню и отчёты открываются в Kitty с оформлением Black Tiffany.
Отчёт закрывается `q` (Neovim: `:q`), меню — `Esc`.

| Otter | Назначение |
|---|---|
| `checkupd` | Проверка после обновления: установленные ядра, модули NVIDIA, DKMS, доступные initramfs, база pacman, упавшие службы, свободное место FAT/EFI и необходимость перезагрузки |
| `errors` | Предупреждения и ошибки за 10/30 минут, 1/6/24 часа: единая временная шкала ядра, системных и пользовательских служб, счётчик по источникам |
| `vms` | Список ВМ, консоль virt-manager, запуск, штатное выключение, создание снимка и возврат к нему |
| `dupes` | Одинаковые файлы: размер → SHA-256 → побайтовое сравнение. По выбору — лишние копии в корзину |
| `growth` | Какие файлы и папки выросли между двумя замерами |
| `kind` | Реальный формат, MIME, SHA-256 и несовпадение сигнатуры с расширением |
| `bdiff` | Изменённые диапазоны байт, добавленные/удалённые строки, энтропия, различия ELF-секций двух файлов |
| `carve` | Поиск сигнатур встроенных объектов и извлечение выбранного диапазона в новый файл |

`log` оставлен совместимым вызовом нового меню ошибок. `vm` по-прежнему открывает
обычный virt-manager, а `vms` — новое меню. Глобальные клавиши/панель не менялись
из-за установки утилит. Старое меню с `force-off` заменено; принудительного
выключения в новом меню нет. CLI-алиас Fish `vmkill` не менялся.

## Python: проверки и ВМ

```sh
workstation-tools post-update                  # JSON, без изменения системы
workstation-tools errors --minutes 30          # текущая загрузка, последние 30 минут
workstation-tools vms                         # только список ВМ
workstation-tools vms --ui                     # интерактивное управление
```

Проверка рассматривает ядра из файлов установленных пакетов `linux` / `linux-lts`,
а не все оставшиеся старые каталоги `/usr/lib/modules`. Если initramfs нельзя
прочитать без root, отчёт говорит «НЕ ПРОВЕРЕНО», а не объявляет его повреждённым.
Права автоматически не повышаются. Порог свободного места EFI 200 МиБ — подсказка,
не гарантия вместимости будущего initramfs. Исправления и обновления не запускаются.

Журнал: текущая загрузка, уровень warning и серьёзнее, максимум 3000 последних
записей на каждый источник. При ограничении доступа или достижении лимита это
отмечается в отчёте. Совпадение событий по времени не доказывает общую причину.

Меню ВМ работает с `qemu:///system`. Выключение: ACPI / guest agent, без `destroy`.
Создание снимка возможно только у выключенной ВМ и запрашивается атомарно.
Если формат диска или конфигурация не поддерживается libvirt, выводится ошибка.
Возврат допускается только к снимку выключенной ВМ; перед ним нужно вручную
ввести имя ВМ. Изменения после снимка будут потеряны. Команды `--force`, изменение
сетей, дисков, автозапуска и запуск ВМ при тестировании не используются.

## Rust: файлы и бинарники

Один нативный бинарник `workstation-files` содержит пять подкоманд. Он не запускает
исследуемые файлы и не отправляет их в интернет. JSON удобен для `jq` и своих скриптов.

```sh
workstation-files dupes ~/Downloads
workstation-files dupes ~/Documents --min-size 1
workstation-files growth ~/Downloads
workstation-files growth ~/Downloads --no-save
workstation-files kind ./sample.bin
workstation-files bindiff ./old.bin ./new.bin
workstation-files carve ./container.bin
workstation-files carve ./container.bin --offset 0x100 --length 4096 --out ./object.bin
```

Вызов того же интерфейса из терминала:

```sh
workstation-tools kind ./sample.bin --ui
workstation-tools bindiff ./old.bin ./new.bin --ui
```

### Дубликаты и размеры

`dupes` по умолчанию учитывает файлы от 1 КиБ, игнорирует симлинки и считает
жёсткие ссылки одним объектом. Отчёт ничего не удаляет. После его просмотра
можно выбрать группу, затем копии и ввести `КОРЗИНА`. Первая копия сохраняется;
перед перемещением SHA-256 проверяется ещё раз. Постоянного удаления нет.

`growth`: первый запуск создаёт базу, последующие показывают разницу и обновляют её.
Отмечаются добавленные, удалённые и изменившиеся по размеру файлы. При неполном
доступе старая база сохраняется. `--no-save` не обновляет базу. Сканирование
пропускает симлинки, `.git`, `.cache`, `node_modules`, `target`, а также собственную
папку состояния. Логические и выделенные по файлам байты не равны уникальному
физическому месту Btrfs: сжатие, reflink и снимки могут менять фактическую экономию.

### Форматы, сравнение и извлечение

`kind` сопоставляет известную сигнатуру с расширением, использует `file` для
описания/MIME. Это не антивирусная проверка. Один заголовок MZ не подтверждает
полноценный PE; отсутствие известной сигнатуры не означает безопасный файл.

`bindiff` сопоставляет байты по одинаковым смещениям, а не функции/инструкции.
Показывает до 200 диапазонов. ASCII-строки: первые 16 МиБ, длина 6–4096,
до 20 000 уникальных; в разнице до 100 строк каждого направления. Энтропия
рассчитывается для всего файла, окна — первые 4096 по 64 КиБ. Полные окна
сохранены в JSON, в интерфейсе есть компактный график. ELF-секции читает `readelf`; метаданные сравниваются по именам секций, содержимое —
по SHA-256 в пределах 64 МиБ суммарно на файл. NOBITS/выход за границы/превышение
лимита помечаются как непроверенное содержимое.
Внешние `file` / `readelf` ограничены по времени 15 секундами.

`carve` находит кандидаты ELF, MZ, PNG, JPEG, PDF, ZIP, GZIP, 7z, XZ. Лимит —
2000 кандидатов, при достижении сканирование останавливается с отметкой в отчёте.
Для PNG предложенная длина определяется границами чанков до IEND без проверки CRC;
для ELF — границами заголовков, таблиц, сегментов/секций, без оверлея. Расширенная
нумерация ELF не поддерживается. Для других форматов длина указывается вручную.
Сигнатура может оказаться случайным совпадением. В Otter копии сохраняются в
`~/Documents/Analysis/extracted/`, с уникальным именем и правами 0600. Уже
существующие файлы не перезаписываются, исходник не меняется, копия не открывается.

## Установка и хранение

```sh
bash ~/dotfiles/scripts/maintenance/build-workstation-files.sh
```

Нужны `rust` (cargo/rustc), `file`, `binutils`, `coreutils`, `fzf`, `fd`, `gio`, Kitty,
Neovim; для ВМ — virsh/virt-manager. В текущем окружении используются имеющиеся
программы; отдельно собран нативный бинарник. Cargo.lock фиксирует зависимости,
сборка — `--release --locked`. Установщик dotfiles также выполняет сборку в разделе
скриптов. Компиляция не требует root.

Бинарник: `~/.local/lib/workstation-tools/workstation-files`.
Отчёты: `~/.local/state/workstation-tools/reports/` (0600).
Замеры размеров: `~/.local/state/workstation-tools/growth/` (0600).
Старые замеры для одного пути заменяются; отчёты сохраняются локально.
Эти утилиты не публикуют их и не отправляют в облако.

Проверки: 6 Rust-тестов, 6 CLI-тестов на временных файлах и 11 Python-тестов.
В частности: неисполнение образцов, отказ перезаписи/выхода за EOF, сигнатура
на границе буфера, жёсткие/символьные ссылки, сохранение базы при ошибках доступа,
подтверждение возврата ВМ и проверка дубликата перед корзиной.
