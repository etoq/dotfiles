# Таймеры и аналитика

Открыть: **Win+Shift+R**, `study` в терминале или `study` в Otter.

1. Нажми **1** — работа, **2** — отдых или **3** — без аналитики.
2. Введи длительность: `50` (минут), `25m`, `90s`, `1h`.
3. Нажми Enter: начнётся обратный отсчёт выбранного типа.

В Polybar справа от рабочих столов показывается только оставшееся время
`ЧЧ:ММ:СС`. Нажатие открывает интерфейс таймера. На паузе значение замирает,
после завершения или отмены блок скрывается.

Все три варианта — таймеры с заданной длительностью. Постоянного режима работы
или отдыха нет. Клавиатура, мышь, приложения и сайты не отслеживаются.

- **Пробел** — пауза / продолжить; пауза не входит в статистику.
- **C** — отменить таймер; сохраняется только уже прошедшее время работы/отдыха.
- **Q / Esc** — закрыть окно. Таймер продолжит идти в фоне; Win+Shift+R вернёт его.
- **D / W / M / A** — сегодня / последние 7 дней / текущий месяц / последние 30 дней.
- **↑ / ↓** — прокрутить таблицу по дням.

Таймер работы добавляет прошедшее время в «Работа», отдыха — в «Отдых».
Третий вариант не добавляет ничего в аналитику. После окончания приходит
уведомление; новый отсчёт сам не начинается. Одновременно работает один таймер.

Отсчёт идёт при блокировке и без движений мыши, но время сна компьютера
исключается. После перезагрузки/выхода из сеанса таймер прерывается, уже
сохранённые секунды остаются. Обновление в фоне — каждые полсекунды;
аварийное завершение может потерять последний интервал сохранения.

Команды:

```sh
study work 50m       # таймер работы
study rest 10m       # таймер отдыха
study timer 5m       # таймер без аналитики
study pause
study resume
study cancel
study status
study report day
study report week
study report month
study report 30 --json
```

В терминале первые три команды открывают интерфейс, в скрипте запускают отсчёт
в фоне. Без длительности предлагают ввести её в интерфейсе.

Время в таблице — десятичные часы: **1.50 ч = 1 час 30 минут**.
Считается фактически прошедшее время таймеров, не вся запланированная длительность.
Интервал через полночь распределяется по соответствующим дням.

Фоновая пользовательская служба `study.service` исполняет только явно запущенные
таймеры. При входе в систему сама отсчёт не начинает. База остаётся локальной:
`~/.local/state/study/activity.sqlite3` (0600; папка 0700).
Прежние интервалы учёта активности сохранены в старой таблице `intervals`,
но исключены из новой аналитики; новые таблицы — `timer_runs` и `timer_intervals`.
Перед переходом существующая база отдельно сохранена рядом с именем
`before-timer-redesign-*.sqlite3`. Для живой базы используйте SQLite backup API.

Состояние службы: `systemctl --user status study.service`.
Журнал: `journalctl --user -u study.service`.
