# Где хранятся данные и как восстановиться

## Три разных хранилища

| Место | Что хранит | Для чего |
|---|---|---|
| https://github.com/etoq/dotfiles | Публичные конфиги, скрипты, документацию, тему | Версии окружения; актуальнее первой облачной копии |
| Proton Drive → Workstation-zer0 | Зашифрованные клиентом архивы выбранных личных папок, включая KeePassXC | Восстановление личных данных; одна проверенная полная версия и до 14 дневных дополнений KeePassXC |
| Локальные Snapper / /var/backups / Documents/Workstation | Снимки и материалы ремонта | Локальный откат и диагностика; не защита от потери самого накопителя |

Пароли KeePassXC не лежат на GitHub. База включена в приватную копию Proton; для открытия нужен мастер-пароль. Для доступа к Proton нужна независимая возможность войти в аккаунт: нельзя рассчитывать только на пароль, запертый внутри этого же Drive.

## Восстановление личных файлов из Proton

1. Войти в Proton Drive с исправного компьютера. В папке Workstation-zer0 выбрать самую новую проверенную полную версию (имя без -partial), а также более новое дополнение KeePassXC, если оно есть. Прежние полные версии удаляются только после проверки новой.
2. Скачать из каждой папки архив `.tar.zst`, `manifest.json`, `SHA256SUMS`. Папки загрузки держать отдельно. Для файлов с паролями/ключами использовать личную папку на зашифрованном диске, закрытую правами 0700.
3. В каждой папке выполнить `sha256sum -c SHA256SUMS`; результат должен быть OK. Дата и результат последней локальной проверки — в ~/.local/state/workstation-backup/status.json; журналы конкретных запусков — в runs/.
4. Распаковать каждую версию в **отдельный пустой каталог**, не поверх HOME. Ниже пример в Bash для уже скачанной полной версии, где текущая папка содержит три её файла:

```bash
umask 077
archive_file='zer0-ИМЯ_ВЕРСИИ.tar.zst'  # подставить имя скачанного архива
restore_target=$(mktemp -d "$HOME/Restore-XXXXXX")
if sha256sum -c SHA256SUMS && tar --extract --zstd \
  --file "$archive_file" \
  --directory "$restore_target" --no-same-owner --same-permissions --acls --xattrs; then
  printf 'Восстановлено в: %s\n' "$restore_target"
else
  printf 'Ошибка проверки или распаковки. Файлы не переносить в HOME.\n' >&2
fi
```

Для дополнения аналогично указать имя скачанного архива -partial и другой пустой каталог. Если дополнение новее полной версии, брать базу KeePassXC из дополнения. Проверить её открытие мастер-паролем в KeePassXC. Затем при закрытых приложениях переносить выбранные файлы в рабочие папки, сохраняя исходные версии до проверки. Закрытые данные не копировать в GitHub.

## Восстановление dotfiles

```bash
git clone https://github.com/etoq/dotfiles.git "$HOME/dotfiles"
```

Каталог .git в новых копиях Proton исключён; история берётся с GitHub, а актуальные файлы конфигурации также есть в самом архиве.

Если каталог уже существует, сначала посмотреть `git status`, сохранить свои правки и проверить remote. Не клонировать поверх существующих файлов.

Конфиги включают настройки конкретного ThinkPad P50, пути и UUID. Перед запуском install.sh читать его параметры и карту [CONFIG-MAP.md](CONFIG-MAP.md). `restore-system.sh --check` только проверяет комплектность и совпадение машины; `--apply` меняет системные файлы и не нужен для обычного использования рабочего ПК.

Пользовательские архивы и системные backup не заменяют установочный носитель. Диски VM не включены в облачное резервирование; работа с ними завершена отдельно.

## Повседневные проверки

```bash
systemctl --failed
systemctl --user --failed
~/.local/bin/check-sleep-callback
~/.local/bin/wispr-a11y-guard
workstation-backup
```

`check-sleep-callback` проверяет конфигурацию, не усыпляет компьютер. `workstation-backup` без параметров не загружает данные. Ручная полная копия: `workstation-backup --run-once`. Автоматически полная копия выполняется по воскресеньям в 20:00, KeePassXC — ежедневно в 19:00; пропущенный запуск догоняется после входа. Политика хранения и управление таймерами — [PROTON-BACKUP.md](PROTON-BACKUP.md).
