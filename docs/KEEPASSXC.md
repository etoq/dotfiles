# KeePassXC: запуск и защита от переполнения AT-SPI

18 октября 2026 KeePassXC 2.7.12-5 завершался SIGABRT до появления окна.
GDB установил: Qt5DBus падал при запросе `org.a11y.atspi.Registry` на шине
доступности. Это происходило и с пустыми временными настройками.

Статистика брокера показала 276 402 636 байт исходящей очереди одному клиенту:
`wispr-flow-linux-helper` (помощник установленного `wispr-flow-appimage`). Он
перестал читать события. Квота UID оказалась исчерпана, поэтому брокер разрывал
новые подключения, в том числе от KeePassXC. После SIGTERM только этому помощнику
Wispr Flow автоматически создал новый, очередь очистилась без перезапуска шины.
Три независимых запуска KeePassXC с временными настройками прошли успешно.

KeePassXC запускается штатным `/usr/bin/keepassxc`, через системный desktop entry
или команду `kp` в Otter. Прежний обход через `systemd-run` и локальный desktop
override удалены: они не устраняли переполнение чужой очереди.

## Защита от повторения

Пользовательский `wispr-a11y-guard.timer` раз в 10 секунд запускает короткую
проверку счётчиков AT-SPI. При очереди от 32 МиБ в двух последовательных
наблюдениях он посылает SIGTERM **только** упакованному помощнику Wispr Flow.
Проверяются UID, путь бинарника, родительский процесс и время создания; pidfd
защищает от повторного использования номера PID. Восстановления записываются
в журнал службы без всплывающих уведомлений (изменено 19 октября по просьбе
пользователя). Текущую диктовку при таком событии может понадобиться повторить.

Это ограниченный обход зависания стороннего помощника, а не исправление его
исходного кода. После обновления Wispr Flow стоит проверить, нужен ли он ещё.
Проверка не читает тексты доступности, буфер обмена, пароли или сообщения D-Bus.
Она не повышает квоты, не перезапускает общую шину и не отключает доступность.

```bash
~/.local/bin/wispr-a11y-guard              # только диагностика
systemctl --user status wispr-a11y-guard.timer
journalctl --user -u wispr-a11y-guard.service --no-pager
systemctl --user disable --now wispr-a11y-guard.timer  # отключить обход
```

База `~/Documents/Пароли.kdbx`, её содержимое и пароль не изменялись. Настройки
интеграции с браузером сохранены. Диагностические отчёты остаются локально в
`~/Documents/Workstation/2026-10-18/keepassxc-repair/`, в GitHub не публикуются.

Метод диагностики очередей: [автор dbus-broker](https://dvdhrm.github.io/2021/04/14/locating-dbus-resource-leaks/).
