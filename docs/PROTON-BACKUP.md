# Proton Drive: подключение резервирования

Состояние: провайдер выбран, официальный CLI 0.9.0 установлен локально. Проверена опубликованная Proton SHA512 для linux/x64. Никаких архивов или загрузок не запускалось, расписания нет, enabled=false. Папка /my-files/Workstation-zer0 пока только указана в плане, в облаке не создавалась.

## Вход

В обычном пользовательском терминале, без sudo:

```sh
~/.local/bin/proton-drive auth login
```

Откроется браузер. Войти/создать аккаунт и завершить авторизацию там, терминал держать открытым до завершения. Пароль и коды 2FA в чат не передавать. Сессия хранится через OS secret store; на этой машине org.freedesktop.secrets предоставляет GNOME Keyring. Не использовать unsafe_file или аргументы команд для паролей.

Вход сам по себе не включает резервирование. После входа нужно проверить доступный объём аккаунта и отдельно запустить первый backup с тестовым восстановлением. На подготовительном этапе не создавать задания синхронизации, не выполнять upload, empty-trash или delete. На выбранных источниках сейчас около 1.4 GiB до исключений, без VM; это не размер всей системы. Бесплатный Proton Drive заявляет 5 GB, доступный остаток конкретного аккаунта ещё не проверен.

## Следующий этап после разрешённого первого запуска

Сохранить версии, права/симлинки в архиве; передавать через официальный клиент с client-side E2EE. До объявления backup рабочим нужно скачать копию, сверить хеш и пробно восстановить файлы в отдельную папку. Локальный staging должен быть закрыт правами 0600/0700. На этапе подготовки staging/ключи/тестовые архивы не создавались. Автоудаление старых облачных копий не настроено.

## Пути

- План: ~/.config/workstation-backup/plan.json (0600), enabled=false.
- Версия/URL/SHA512: configs/workstation-backup/proton-cli.json.
- Бинарный файл: ~/.local/lib/proton-drive/0.9.0/proton-drive.
- ~/.local/bin/proton-drive — launcher из dotfiles, выставляет WARNING для минимизации логов.
- proton-drive-install повторно проверяет установленный бинарник; при необходимости загружает закреплённую версию с проверкой SHA512. Вход и загрузку данных не выполняет.
- Статус Control Deck: Proton — нужен вход. last_success=null означает, что успешных резервных копий ещё нет.
