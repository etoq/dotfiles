# Proton Drive: резервирование

Официальный CLI 0.9.0 установлен локально с проверкой опубликованной SHA512; вход выполнен. Копирование запускается вручную, расписание выключено (`enabled=false`, `schedule=null`).

Полная версия предшествует последним изменениям dotfiles. Более свежие публичные конфиги/скрипты опубликованы в GitHub; текущую облачную копию это не обновляет. Для восстановления пользовательских данных нужны полная версия **и** более новое дополнение KeePassXC.

Состав выбранных источников: dotfiles с историей Git, Obsidian, проекты/заметки, профили Ghidra/Throne, SSH, keyrings, база KeePassXC и настройки. Это не образ всего диска: VM, всё HOME и весь /etc в такую копию не входят. Точные источники — приватный plan.json. Базы паролей и приватные профили в публичный Git не попадают.

База KeePassXC защищена мастер-паролем; пользователь подтвердил отсутствие ключевого файла/аппаратного ключа. Мастер-пароль не считывался, открытый текст паролей не экспортировался.

## Обычные команды

В пользовательском терминале, без sudo:

```bash
workstation-backup              # только показать локальный план
workstation-backup --run-once   # новая полная версия + скачивание и тест восстановления
```

`--only` вместе с `--run-once` выбирает точный путь из sources, параметр можно повторять. Такой запуск создаёт дополнение `-partial`, а не полную копию. Он не удаляет прежние версии. План включает KeePassXC и в следующую полную копию.

Новый вход при утрате сессии: `proton-drive auth login`, завершить его в браузере. Сессия хранится в OS keychain (GNOME Keyring). Пароль/2FA не передавать в чат или аргументах команд. Доступ к аккаунту и recovery-данные нужно иметь отдельно от самого Drive.

## Как проверяется копия

GNU tar+zstd сохраняет права, ACL/xattrs и симлинки; манифест содержит SHA256 файлов. Имена/типы архивных записей проверяются перед отправкой. Изменение исходных файлов при tar приводит к повтору (до трёх попыток) или отказу от загрузки.

Официальный Proton CLI шифрует файлы до передачи через client-side E2EE. После загрузки архив, manifest.json и SHA256SUMS скачиваются обратно. Проверяются хеш архива и sidecar-файлы, затем все записи восстанавливаются в отдельную закрытую временную папку с проверкой содержимого, прав и ссылок. Исходные данные не перезаписываются. Staging после завершения очищается.

Это файловая копия живых данных. Консистентность открытых прикладных баз не гарантируется; для восстановления базы нужна её штатная проверка приложением. Новая версия не заменяет старую. При ошибке загрузки облачная папка может быть неполной и не считается подтверждённой.

Файл статуса сохраняет последнюю успешную полную копию и дополнение при последующих ошибках; успешность обновляется только после проверки восстановления. Автоматического удаления старых облачных копий нет. Доступный остаток квоты не предполагается по номинальному тарифу; при нехватке места загрузка завершается ошибкой.

## Пути и восстановление

- Приватный план: ~/.config/workstation-backup/plan.json, 0600.
- Статус/манифесты/результаты/закрытые логи: ~/.local/state/workstation-backup/, 0700.
- Временные файлы: ~/.local/share/workstation-backup/staging/, 0700.
- Клиент: ~/.local/lib/proton-drive/0.9.0/proton-drive; launcher ~/.local/bin/proton-drive.
- Источник закреплённой версии/URL/SHA512: configs/workstation-backup/proton-cli.json. proton-drive-install проверяет бинарник, но не входит в аккаунт и не загружает данные.
- Control Deck показывает последнюю операцию/успех/ошибку; пометка «дополнение» означает частичную копию.
- Пошаговое восстановление — [RECOVERY.md](RECOVERY.md).
