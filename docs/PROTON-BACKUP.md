# Proton Drive: подключение резервирования

Состояние: официальный CLI 0.9.0 установлен локально; пользователь завершил вход. Доступ подтверждён успешным read-only filesystem info /my-files. Проверена опубликованная Proton SHA512 для linux/x64. Первая ручная копия выполнена и полностью проверена 18 октября 2026, расписания нет, enabled=false. В облаке создана папка версий /my-files/Workstation-zer0.

## Вход

В обычном пользовательском терминале, без sudo:

```sh
~/.local/bin/proton-drive auth login
```

Откроется браузер. Войти/создать аккаунт и завершить авторизацию там, терминал держать открытым до завершения. Пароль и коды 2FA в чат не передавать. Сессия хранится через OS secret store; на этой машине org.freedesktop.secrets предоставляет GNOME Keyring. Не использовать unsafe_file или аргументы команд для паролей.

Вход сам по себе не включает резервирование. После входа нужно проверить доступный объём аккаунта и отдельно запустить первый backup с тестовым восстановлением. На подготовительном этапе не создавать задания синхронизации, не выполнять upload, empty-trash или delete. На выбранных источниках сейчас около 1.4 GiB до исключений, без VM; это не размер всей системы. Бесплатный Proton Drive заявляет 5 GB, доступный остаток конкретного аккаунта ещё не проверен.

## Следующий этап после разрешённого первого запуска

Сохранить версии, права/симлинки в архиве; передавать через официальный клиент с client-side E2EE. До объявления backup рабочим нужно скачать копию, сверить хеш и пробно восстановить файлы в отдельную папку. Локальный staging должен быть закрыт правами 0600/0700. На этапе подготовки staging/ключи/тестовые архивы не создавались. Автоудаление старых облачных копий не настроено.

## Пути

- План: ~/.config/workstation-backup/plan.json (0600), enabled=false.
- Версия/URL/SHA512: configs/workstation-backup/proton-cli.json.
- Бинарный файл: ~/.local/lib/proton-drive/0.9.0/proton-drive.
- ~/.local/bin/proton-drive — launcher из dotfiles, выставляет WARNING для минимизации логов.
- proton-drive-install повторно проверяет установленный бинарник; при необходимости загружает закреплённую версию с проверкой SHA512. Вход и загрузку данных не выполняет.
- Статус Control Deck берётся из приватного status.json: дата последней полностью проверенной копии, текущая операция или ошибка.

## Ручная копия с полной проверкой

workstation-backup без параметров показывает только локальный план. После явного разрешения пользователя выполняется workstation-backup --run-once: архив GNU tar+zstd с правами, ACL/xattrs и симлинками; манифест файлов с SHA256; версия в /my-files/Workstation-zer0/<UTC timestamp>. Файлы шифрует официальный клиент Proton до передачи. Перед отправкой проверяются имена и типы членов архива. Если tar сообщает об изменении исходных файлов, до трёх попыток; неисправный архив не отправляется.

После upload скачиваются архив, manifest.json и SHA256SUMS. Сверяются хеш архива и sidecar-файлы, затем все файлы восстанавливаются в закрытую временную папку. Проверяются SHA256/размер/права регулярных файлов, директории, симлинки и hardlinks. Исходные папки не перезаписываются. Временные копии удаляются после завершения; локально остаются приватные манифест/результат/лог в ~/.local/state/workstation-backup/runs. Новая версия не заменяет прошлые и не удаляет их автоматически. При сбое облачная версия может остаться неполной и не считается подтверждённой; last_success обновляется только после полного восстановления.

Локальный staging на зашифрованном разделе закрыт правами 0700/0600. Это файловая копия живых пользовательских данных: консистентность транзакций открытых прикладных баз данных не гарантируется; диски VM не включены. Для восстановления прикладной базы требуется её штатная проверка.

Автоматическое расписание остаётся выключенным (schedule=null, enabled=false); --run-once означает разовый ручной запуск. Точный остаток квоты аккаунта CLI здесь не предоставляет, при исчерпании места upload должен завершиться ошибкой; свободные 5 GB не предполагаются без проверки.

Для аварийного восстановления сначала скачать нужную версию в отдельную папку, сверить SHA256SUMS и manifest.json, затем восстанавливать в пустой каталог, а не поверх HOME. Сохранять доступ к аккаунту Proton и recovery-данные отдельно от самого Drive.

## KeePassXC и дополнения

Путь базы добавлен в приватный plan.json, настройки ~/.config/keepassxc тоже включены. Пользователь подтвердил отсутствие ключевого файла/аппаратного ключа: сохранённая .kdbx открывается его мастер-паролем. Открытый текст паролей не экспортируется. Файлы .kdbx/.keyx и ключи исключены из Git; в GitHub попадают только конфиги и скрипты.

Поддерживается --only с точным путём из sources (можно повторять) совместно с --run-once. Дополнение получает scope=partial и suffix -partial; оно не заменяет полную копию. Полный следующий запуск без --only включит и базу KeePassXC. last_full_success и last_full_verified_remote отдельно сохраняют сведения о последней полной версии.

Мастер-пароль не считывался и не сохранялся. Для полного восстановления брать последнюю полную версию плюс более новое дополнение; исходную полную копию не удаляли.
