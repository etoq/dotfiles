# Proton Drive: автоматическое резервирование на 2 ГБ

Официальный CLI 0.9.0 установлен локально с проверкой SHA512; вход выполнен. План включён по разрешению пользователя 19 октября 2026. Пользовательские systemd-таймеры запускаются в его сеансе и догоняют пропущенный запуск после входа.

## Расписание и хранение

| Задание | Время (Asia/Yekaterinburg) | Что сохраняется |
|---|---|---|
| Полная копия | Воскресенье, 20:00, случайная задержка до 5 минут | Все выбранные пользовательские источники; одна подтверждённая полная версия |
| KeePassXC | Ежедневно, 19:00, задержка до 5 минут | База и настройки; последние 14 разных дневных версий, последняя версия каждого дня |

Данные: dotfiles, Obsidian, проекты/заметки, профили Ghidra/Throne, SSH, keyrings, база KeePassXC и настройки. Обои включены. Из dotfiles исключён только дублирующий каталог `.git`; история конфигов опубликована в https://github.com/etoq/dotfiles. Остальные исключения — кеши/генерируемые зависимости из локального плана. Измерение до настройки: новая полная копия около 803 МиБ.

Это не образ всего диска: VM, всё HOME и весь /etc в копию не входят. Консистентность открытых прикладных баз не гарантируется; для восстановленной базы нужна её штатная проверка приложением. База KeePassXC защищена мастер-паролем; пользователь подтвердил отсутствие отдельного ключевого файла/аппаратного ключа.

## Как заменяется версия

1. Создать новую копию, сохранив прежнюю.
2. Загрузить через официальный клиент с client-side E2EE.
3. Скачать архив, manifest.json и SHA256SUMS обратно, сверить хеши.
4. Восстановить все записи в отдельную закрытую временную папку и проверить содержимое/права/ссылки.
5. Только после успешного восстановления убрать устаревшие версии.

Кандидаты для удаления выбираются **только** из локального журнала успешных проверенных восстановлением запусков. Проверяются UID родительской папки, UID версии, отсутствие общего доступа и совпадение скачанного манифеста с локальным. Удаление идёт через конкретный UID в корзине; общая корзина Proton не очищается. Чужие файлы, неизвестные/неподтверждённые версии не удаляются. Прерванное удаление имеет отдельный локальный журнал и продолжается при следующем запуске.

Если источник исчез из новой полной копии, прежняя версия, которая его содержала, не удаляется автоматически. Если изменилась идентичность папки или манифест не совпал, очистка останавливается. Результат уже проверенной новой копии при этом сохраняется, ошибка видна в статусе.

## Ограничение объёма и ошибки

- Бюджет — 2 000 000 000 байт; резерв — 100 000 000 байт; максимум одного архива — 900 000 000 байт.
- Перед отправкой проверяется размер `/my-files` через CLI (включая его удалённые потомки), плюс новый архив/sidecar-файлы и резерв. Это предел нашего плана, а не чтение квоты всего аккаунта: другие разделы Drive тоже могут занимать место.
- Если места недостаточно, старая подтверждённая копия не удаляется ради новой. При росте объёма нужно пересмотреть состав/хранилище.
- Ошибка загрузки/проверки может оставить неподтверждённую папку; автоматически считать её успешной или удалять как проверенную скрипт не будет. Она может потребовать отдельной проверки, если занимает место.
- При ошибке есть уведомление и статус Control Deck; systemd делает до трёх попыток с интервалом 30 минут в пределах трёх часов. Одновременные задания ожидают общий lock до 30 минут.
- Сервис работает в пользовательском сеансе: доступ к Proton зависит от действующей сессии в OS keychain. Компьютер ради копии не пробуждается.

GNU tar+zstd сохраняет права, ACL/xattrs и ссылки. При изменении исходных файлов tar повторяется до трёх раз; некорректный архив не отправляется. Временный staging закрыт правами 0700/0600 и очищается после завершения. Мастер-пароль не считывается, открытый текст паролей не экспортируется.

## Команды

```bash
workstation-backup                         # только показать план
workstation-backup --run-once              # ручная полная копия с той же проверкой и хранением
systemctl --user start workstation-backup@keepass.service  # разовая копия KeePassXC
systemctl --user list-timers 'workstation-backup*'
journalctl --user -u 'workstation-backup@*' --no-pager
```

`--only` с `--run-once` по-прежнему создаёт частичную копию точных источников из плана. Автоматическое хранение KeePass применяется только к дополнениям с тем же составом источников. Произвольные частичные копии не удаляются по этой политике.

Отключение будущих автоматических запусков:

```bash
systemctl --user disable --now workstation-backup-full.timer workstation-backup-keepass.timer
```

Это не останавливает уже выполняющуюся копию. При необходимости остановить её отдельно: `systemctl --user stop workstation-backup@full.service workstation-backup@keepass.service`. Флаг `enabled=false` в приватном плане тоже запрещает задания с `--scheduled`; ручной `--run-once` остаётся явным запуском.

## Пути

- План с личным путём .kdbx и политикой: ~/.config/workstation-backup/plan.json (0600).
- Таймеры/сервис/уведомление: ~/.config/systemd/user/workstation-backup*; источники configs/systemd/user/.
- Статус и манифесты: ~/.local/state/workstation-backup/ (0700). В runs/<версия>/result.json — доказательство завершённой проверки; retention.json — журнал удаления конкретной старой версии.
- Staging: ~/.local/share/workstation-backup/staging/ (0700).
- Клиент: ~/.local/lib/proton-drive/0.9.0/proton-drive; launcher ~/.local/bin/proton-drive.
- Свежий пример плана в Git отключён и не содержит базы, пути к ней или авторизации: configs/workstation-backup/plan.example.json. Установщик связывает unit-файлы; включает backup-таймеры только при уже включённом приватном плане.
- Восстановление — [RECOVERY.md](RECOVERY.md).

При переустановке нельзя считать неизвестные облачные папки автоматически управляемыми: журнал проверок/удалений остаётся локальным. Старые версии сначала нужно проверить; одного совпадения имени папки для удаления недостаточно.

Новый вход при утрате сессии: `proton-drive auth login`, завершить его в браузере. Сессия — OS keychain (GNOME Keyring). Доступ к аккаунту и recovery-данные хранить отдельно от самого Drive.
