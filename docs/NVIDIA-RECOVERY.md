# NVIDIA: подготовка возврата к рабочей 470

19 октября 2026 подготовлен локальный комплект из **семи** пакетов установленной
ветки 470.256.02. Это реконструкция фактически установленных файлов через
штатный makepkg, не исходные архивы прежнего сборщика. Версии/зависимости,
скрипт установки и исходники с уже применёнными исправлениями ядра сохранены.
Отладочная обработка/strip и изменение сжатия man-страниц отключены.

## Что проверено

- Все семь архивов приняты pacman как пакеты; SHA256 записаны в манифесте.
- Установка выполнена через fakeroot **только во временное дерево** с отдельной
  базой pacman, без зависимостей и скриптов установки; дерево удалено после теста.
- pacman -Qkk в тестовом дереве: 0 изменённых файлов по всем семи пакетам.
- 554 обычных файла побайтно сверены с рабочей системой; также проверены права
  и цели симлинков. Дополнительная проверка сверяет пакеты и живые файлы перед
  созданием системного снимка.

Это проверка восстановления содержимого пакетов, а не загрузка драйвера,
проверка DKMS/графического сеанса или фактический откат после установки 580.

## Где лежит комплект

`~/Documents/Workstation/2026-10-18/system-repair/nvidia470-rollback/`

- packages/ — семь .pkg.tar.zst, суммарно около 310 МиБ;
- manifest.json — точные версии, SHA256 и метаданные файлов;
- SHA256SUMS — контрольные суммы архивов;
- isolated-verification.json — результат независимой установки;
- logs/isolated-install.log — журнал установки и pacman -Qkk;
- recipes/ — локальные PKGBUILD и исходный install script для происхождения.

Одноразовые сборщик и проверка сохранены рядом, в system-repair/
repack-installed-nvidia.py и verify-nvidia470-recovery.py. Их работа не меняла
пакеты хоста. Временные рабочие деревья автоматически удалены. Архивы пакетов
остаются локально: в GitHub и Proton они не отправлялись.

## Системная резервная копия завершена

19 октября, 07:41:41, помощник успешно завершил копирование в
`/var/backups/nvidia470-recovery-20261019-074138`.
Сохранены семь пакетов, /boot с EFI (архив около 1.09 ГиБ), модули и настройки
(около 52 МиБ). Оба сжатых архива проверены помощником; записаны SHA256.
Загруженный драйвер — 470.256.02; ядра — 6.18.57-1-lts и 7.2.10-arch1-1.
Отчёт root:eto, 0640 подтверждает завершение без установки пакетов и перезагрузки.

Повторное создание такого комплекта, если состояние системы изменится:

Из обычного терминала пользователя:

```bash
sudo python ~/dotfiles/scripts/maintenance/nvidia470-system-backup.py system-backup
```

Root нужен для чтения initramfs и защищённых системных файлов. Команда:

1. Сверяет семь пакетов с SHA256/живыми файлами и прежней проверкой установки.
2. Проверяет загруженную 470.256.02, vermagic модулей обоих установленных ядер
   и соответствие initramfs, наличие смонтированного EFI-раздела.
3. Создаёт закрытый локальный каталог /var/backups/nvidia470-recovery-*.
4. Копирует пакеты, сохраняет /boot вместе с EFI, действующие NVIDIA-модули,
   конфиги загрузки/сна, хуки, исходную метаинформацию pacman и ключ DKMS.
5. Проверяет сжатые архивы и записывает SHA256. До завершения каталог имеет
   суффикс .incomplete; успешный комплект переименовывается атомарно.

Доступ к архивам — только root, 0700/0600; они остаются на зашифрованном
локальном разделе и не входят в текущий выбранный набор Proton. Модули,
пакеты, сервисы, загрузочная конфигурация и BIOS этой командой не меняются;
сон и перезагрузка не выполняются.

Без закрытых данных отчёт о завершении сохраняется в
`/run/nvidia470-recovery-1000/report.json`, доступен пользователю только на чтение.
После смены установленных версий/файлов проверка остановится: комплект нужно
пересобрать для нового состояния, а не считать старый автоматически актуальным.

Повторная проверка без root и без создания архивов:

```bash
python ~/dotfiles/scripts/maintenance/nvidia470-system-backup.py check
```

## Проверка транзакций завершена

`system-repair/verify-nvidia-transactions.py` клонирует только метаданные текущей
локальной базы pacman во временный каталог под fakeroot. В него устанавливается
содержимое 470, затем полный набор 580 и обратно 470. Разрешение зависимостей
включено; скрипты установки и хуки отключены. После каждой транзакции отдельно
сверяются все целевые имена и версии: успешный выход pacman после предложения
пропустить недоступный пакет не считается проверкой полного перехода.

В исходном наборе не хватало egl-wayland2, egl-gbm и egl-x11. Архивы скачаны из
зеркала официального репозитория Arch и подписи проверены через pacman-key.
Они лежат только в system-repair/nvidia580-dependencies/, в систему не установлены.

Итог: 10 пакетов в прямой транзакции, семь в обратной; после возврата pacman -Qkk
показывает 0 изменённых файлов по всем семи пакетам 470. Журнал и результат:
logs/nvidia-transactions.log и logs/nvidia-transactions-verification.json.
Это не проверяет реальную работу скриптов пакета, DKMS-хуков, загрузку GPU или сон.
Три новые библиотеки после пробного возврата остаются в тестовом дереве; весь
каталог затем удаляется. Хост и его база pacman не изменялись.

## Сохранение рабочего сна при будущем переходе

У 580 обнаружены два отличия: post_install включает NVIDIA suspend/resume/hibernate,
а usr/lib/modprobe.d/nvidia-580xx-utils.conf задаёт PreserveVideoMemoryAllocations=1.
Они не соответствуют проверенной здесь callback-конфигурации.

В dotfiles подготовлены изменения, **ещё не применённые к /etc и /usr/local**:

- хук 66-nvidia470-sleep-policy теперь также реагирует на пакеты 580;
- помощник создаёт одноимённый /etc override для vendor-конфига 580, сохраняя
  blacklist/softdep и меняя только PreserveVideoMemoryAllocations на 0;
- отключаются также nvidia-suspend-then-hibernate и исполняемый vendor sleep hook;
- хук копирования образов в EFI учитывает DKMS-пакет 580.

Проверены идемпотентность, сохранение vendor-файла, blacklist/softdep, параметра
EnableMSI и существующей схемы 470 в scripts/tests/test_nvidia_sleep_policy.py.

## Установка подготовленного набора 580

Подготовлены scripts/maintenance/nvidia-transition.py и соседний фиксированный
nvidia-transition-plan.json: десять точных имён/версий/SHA256, оба ядра, идентификатор
машины и путь root-комплекта 470. Сам скрипт без аргументов только проверяет комплект:

```bash
python ~/dotfiles/scripts/maintenance/nvidia-transition.py
```

Сохранить документы и завершить приложения, использующие GPU. Затем в обычном
терминале с доступным stdin выполнить:

```bash
sudo python ~/dotfiles/scripts/maintenance/nvidia-transition.py --apply580
```

Root нужен для pacman, системных хуков, DKMS, initramfs и EFI. Пароль вводится
только в локальном терминале sudo. Команда не перезапускает SDDM, не выгружает
загруженный модуль, не усыпляет и не перезагружает ноутбук.

Перед заменой проверяются вся root-резервная копия по SHA256, личность машины,
ядра, исходные версии 470 и все архивы. Создаётся отдельный закрытый каталог
/var/backups/nvidia-transition-ДАТА-ВРЕМЯ: туда копируются архивы установки,
самостоятельный скрипт возврата, фиксированный план, необходимые помощники и
предыдущие системные хуки. Команда возврата печатается до начала pacman.

Развёртываются только необходимые NVIDIA/EFI-хуки и помощники. Затем pacman -U
предлагает заменить конфликтующие пакеты 470 пакетами 580: отвечать y только
на эти замены и установку перечисленного набора. Принудительного удаления
зависимостей и глобального --noconfirm нет. После транзакции повторно применяется
callback-политика, даже если pacman завершился ошибкой.

Скрипт проверяет точные установленные версии, DKMS и версии четырёх модулей для
обоих ядер, пересобирает mkinitcpio, синхронизирует EFI и сверяет хеши всех четырёх
копий образов. Дополнительно проверяются эффективное PreserveVideoMemoryAllocations=0,
неисполняемый vendor sleep hook и отключённые NVIDIA sleep services. EFI-помощник
проверяет место для всей последовательности атомарного копирования до замены
первого файла. Существующие посторонние EFI-файлы не удаляются.

Журнал — transition.log, результат — result.json внутри каталога перехода.
Доступный пользователю итог без закрытых данных сохраняется также в
/run/nvidia-transition-1000/report.json.

Только после **Completed. Installed NVIDIA: 580.178.04** вручную перезагрузиться
в Linux LTS. До перезагрузки в памяти остаётся 470, а библиотеки на диске уже 580:
не запускать сон и новые GPU-приложения в этом промежутке. Если появилась STOP,
не перезагружаться до разбора журнала или успешного возврата к 470.

После загрузки проверить:

```bash
uname -r
nvidia-smi
~/.local/bin/check-sleep-callback
```

Сначала проверить изображение, оба доступных монитора и обычные приложения.
Сон проверять отдельно с сохранённой работой; прежний успешный сон с 470
не доказывает работу 580 на этом ноутбуке.

## Возврат на 470 при проблеме с графикой

Если доступен TTY, перейти Ctrl+Alt+F3 и войти пользователем. Если графическая
загрузка мешает, в GRUB выбрать Linux LTS, нажать e и однократно добавить к строке
linux параметр systemd.unit=multi-user.target; загрузить Ctrl+X. BIOS не менять.

```bash
sudo python /home/eto/dotfiles/scripts/maintenance/nvidia-transition.py --restore470
```

Возврат использует семь архивов из защищённого root-комплекта, без сети. Он
переустанавливает их одной транзакцией, сохраняет callback-сон, собирает DKMS
для обоих ядер, mkinitcpio и EFI, проверяет результат. Три дополнительные EGL-
библиотеки остаются установленными; их удаление не требуется для возврата драйвера.
После **Completed. Installed NVIDIA: 470.256.02** перезагрузиться вручную.

Если HOME-репозиторий недоступен, использовать напечатанную при установке
команду с сохранённой копией скрипта в /var/backups/nvidia-transition-ДАТА-ВРЕМЯ/.
У неё есть собственные помощники и план, зависимости от GitHub или файлов HOME
для возврата нет. При изменении установленных ядер помощник останавливается:
потребуется отдельный план восстановления под фактические версии.

Если не загружается даже текстовый режим, нужен установочный носитель Arch и
восстановление из chroot с правильным монтированием зашифрованного корня и EFI.
Это отдельная процедура по фактическому состоянию загрузки. Метаданные pacman
из архива нельзя просто распаковывать поверх изменившейся базы. Сам /boot архив
— запас для восстановления, а не команда для слепой распаковки поверх новых ядер.

11 тестов проверяют политику сна, отказ при неверном архиве/имени/модуле,
повторное применение сна при сбое pacman, запрет действий без root, автономность
помощников возврата и сохранность EFI при нехватке места. Реальная установка и
загрузка 580 пока не выполнялись.

Рабочий драйвер сейчас остаётся 470.256.02. Автоматической установки 580 или
восстановления поверх живой системы в инструменте резервирования нет.

Формат и упаковка: [Arch PKGINFO](https://man.archlinux.org/man/PKGINFO.5.en);
архивы сформированы установленным makepkg, а не самодельной заменой формата.
