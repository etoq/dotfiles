# AwesomeWM · Black Tiffany

Awesome — текущий рабочий оконный менеджер; bspwm сохранён как альтернативный сеанс. В обоих сеансах используется единственная панель Polybar Tiffany Orbit. Встроенные wibar, центр управления и трей Awesome удалены; трей теперь принадлежит Polybar. Войти в Awesome можно через выбор сеанса в SDDM.

Для отдельного тестового окна без смены текущего WM: `awesome-preview`. Ctrl+Shift захватывает клавиатуру Xephyr, Win+Ctrl+Shift+Esc закрывает тестовый Awesome.

## Управление

| Win+P | Скрыть / показать Polybar |
| Win+Shift+Z / O / T / S | Zen / Obsidian / AyuGram / Throne |

| Win+Shift+V / G | virt-manager / Ghidra |
| Win+Shift+N / P | Yazi / pavucontrol |
| Win+Shift+X / C / K / R | Пипетка / калькулятор / календарь / работа, отдых и таймер |
| Win+1…7 | Переключить рабочий стол |
| Win+Shift+1…7 | Перенести окно на стол |
| Win+H/J/K/L | Фокус по направлению |
| Win+Alt+H/J/K/L | Поменять окна местами |
| Win+Ctrl+H/J/K/L | Изменить размер / пропорцию |
| Win+Space | Плавающее / тайловое окно |
| Win+Ctrl+Space | Следующая раскладка окон |
| Win+F / M / C | Полный экран / развернуть / закрыть |
| Win+Shift+Enter | Показать / скрыть scratch-терминал |
| Win+F1 | Список горячих клавиш |
| Win+Ctrl+R | Проверить конфиг и перезапустить Awesome |
| Win+Shift+L / Win+Shift+Esc | Заблокировать / меню питания |

Буквенные сочетания привязаны к физическим клавишам, чтобы работать в US и RU. Приложения открываются на текущем столе, без автоматического переноса на заранее назначенные столы. Otter сохраняет размер 500×420, диалоги и служебные окна остаются плавающими.

Win+Shift+A/D для ChatGPT/Discord восстанавливают существующее окно, в том числе
скрытое в трей, и переключаются на его стол. Если приложение ещё не запущено,
запускается один экземпляр; повторные нажатия во время запуска не создают новые.
Win+C выполняет обычное закрытие окна для всех приложений, как и раньше.
Если ChatGPT или Discord скрывается в трей, Win+Shift+A/D возвращает его окно.

Polybar резервирует место через EWMH strut; дополнительного верхнего padding нет. Ghidra запускается через `reverse-ghidra`, сохраняющий `_JAVA_AWT_WM_NONREPARENTING=1` для Java UI.

Конфиги: `~/.config/awesome/rc.lua`, `theme.lua`, `ui.lua` (только рабочие столы и IPC). Службы сеанса запускает `awesome-session-start`; sxhkd в Awesome не запускается, чтобы не конкурировать за клавиши.

Проверены запуск панели, геометрия окон, отсутствие привязок Ghidra / virt-manager / Obsidian к столам, скрытие / показ панели и 20 запусков горячих клавиш в US/RU в изолированном X11-сеансе. Проверка синтаксиса: `awesome -k`.

Win+F1 показывает буквенные названия клавиш вместо физических кодов `#42`, `#24` и т. п.; сами привязки сохраняют работу в US/RU. Otter центрируется после начальной настройки окна, включая восстановление после перезапуска WM; размер остаётся 500×420.

Alt+Shift переключает US/RU средствами XKB. Калькулятор и другие команды не меняют набор раскладок. Ctrl+Super+B не назначен; Control Deck открывается Win+Shift+B. Календарь использует отдельное окно до 1400×900, шрифт 18 и тему Tiffany.

Win+Shift+X запускает прежнюю пипетку Gpick через `~/bin/xcolor-pick`.
Повторное нажатие отменяет выбор; бездействующий выбор отменяется через 2 минуты.
После получения цвета процесс пипетки завершается, цвет остаётся в буфере обмена.

Калькулятор Win+Shift+C / Otter `calc` — отдельное немодальное GTK-окно
Black Tiffany (`tiffany-calculator`) с вычислениями через установленный qalc.
Rofi для калькулятора не используется. Работают Alt+Tab, Win+цифра и обычное
переключение фокуса. Повторный вызов показывает существующее окно; `calc 2+2`
вычисляет выражение в нём. История последних 30 выражений сохранена в прежнем
`~/.local/state/otter-tools/calc-history.json` (0600), если XDG_STATE_HOME не переопределён.
Enter вычисляет, Ctrl+L очищает ввод, Ctrl+C копирует результат (если текст не выделен), Ctrl+Shift+C всегда копирует результат, Esc закрывает.
`ans` подставляет последний результат; единицы измерения и hex/dec обрабатывает
Qalculate. Внешний `hex(выражение)` поддерживается как формат вывода, по образцу
Python: переводится в `(выражение) to hex`. У самого Qalculate функция `hex()`
имеет другое значение — читает аргумент как число в основании 16. Например,
`hex(0x5641f74a5000 - 0x2f000)` выводит `0x5641F7476000`.
Если в выражении два или больше числа с префиксом `0x`, результат автоматически
выводится в HEX. Явный `to dec`, `to bin` или другой перевод сохраняет приоритет.
Кнопка «Скопировать», Ctrl+C без выделения и Ctrl+Shift+C передают обычный текст в CLIPBOARD через xclip;
он остаётся доступен после закрытия калькулятора. Минус копируется как ASCII `-`,
при вычислении копирование предыдущего результата заблокировано.
Вычисления асинхронные, ограничены 8 секундами; закрытие окна завершает
активный процесс qalc. Формулы не выполняются через Python eval или оболочку.
В изолированном X11 проверены отсутствие захвата клавиатуры, переключения
столов/окон, арифметика, отрицательные числа, ans, HEX, единицы, clipboard и
единственный экземпляр. GUI-пакеты дополнительно не устанавливались.

Навигация `Win+H/J/K/L`, Alt+Tab и история фокуса исключают Polybar и служебные окна; `Win+Alt+H/J/K/L` переставляет только обычные тайловые окна. `Win+T` снимает полный экран / максимизацию и возвращает тайловый режим. Код отбора окон: `~/.config/awesome/navigation.lua`. Перезагрузка WM сохраняет уже настроенную активную раскладку US/RU.

По умолчанию основное окно находится справа и занимает 56% ширины.
При двух окнах левое занимает оставшиеся 44%; третье, четвёртое и последующие
добавляются в левую колонку сверху вниз. Основное правое окно сохраняется.
Используется зеркальная раскладка awful.layout.suit.tile.left.

Win+Shift+1…7 переносит обычное тайловое окно в раскладку другого стола:
сбрасываются fullscreen/maximized и частичные maximized-флаги, окно добавляется
в конец порядка тайлов, сохраняя основное окно справа. Явно плавающие окна и
окна фиксированного размера сохраняют свой режим. Нажатие номера текущего
единственного стола ничего не меняет. В `navigation.move_to_tag` учитывается,
что Awesome сам делает развёрнутое окно неявно плавающим.

Kitty не восстанавливает размер/развёрнутое состояние из общего кэша
(`remember_window_size no`); обычные новые Kitty начинают без maximized.
Специальные команды вроде checkupd сохраняют явный `--start-as maximized`.
Проверено в отдельном X11-сеансе на настоящих окнах Kitty: пять переносов
3↔4 реальными Win+Shift+цифра, отсутствие перекрытия, сохранение правого master
и отдельная проверка сохранения режима и размера плавающего окна.

Flameshot: для класса flameshot/Flameshot и типа utility задано отдельное
размещение поверх физической геометрии монитора, без рамки, с ontop.
Стандартный no_offscreen с учётом workarea сдвигал слой захвата с (0,0)
на (0,44), оставляя сверху живой Polybar и показывая его копию ниже внутри
снимка. Исправление не меняет отступы обычных окон или окно настроек Flameshot.
В изолированном Awesome/Xvfb с реальным Flameshot и dock-strut 44 проверено:
до исправления 0,44,1920,1080; после 0,0,1920,1080; workarea обычных окон
по-прежнему начинается на y=44. Конфигурация применена в текущем сеансе
через awesome-client без перезапуска программ.
Документация Flameshot: https://github.com/flameshot-org/flameshot/blob/master/docs/UsageX11MinimalWM.md

20 октября на столе 2 обнаружена пропорция 0.99, сжавшая Kitty до 1 пикселя.
Восстановлена 0.56. Для горизонтальных tile/tile.left добавлено ограничение
master_width_factor 0.30–0.70, действующее при изменении мышью и клавишами.
Это сохраняет возможность ручной настройки без почти полного исчезновения
соседней колонки.
