# Wispr Flow и Soniox: русский язык и reverse engineering

## Wispr: контекст приложений

В установленной сборке `wispr-flow-appimage 1.0.4+wispr1.6.957-1` пустой
ответ helper и Linux-идентификаторы приложений мешали классификации контекста.
`wispr-context` читает только X11-метаданные активного окна: WM_CLASS, заголовок
и PID. Для терминала проверяет имена исполняемых файлов дочерних процессов.
Содержимое переписок, буфер обмена и вывод терминала эта добавка не читает.

- AyuGram/Telegram/64Gram → Telegram из каталога Wispr.
- ChatGPT Desktop и Claude Desktop → их известные идентификаторы.
- Codex/Claude/Gemini/Aider/OpenCode в терминале → `codingCliAgent`.
- В браузере распознаются только явные окончания заголовка ChatGPT, Claude,
  Gemini, NotebookLM. Это эвристика, URL не читается и не выдумывается.
- Полноценное чтение текстового поля, истории чата и страницы не добавлено.
  Настройка стиля и серверная обработка по-прежнему зависят от самого Wispr.

Создана отдельная копия runtime в `~/.local/lib/wispr-context-runtime`.
Патчируются только два места получения AppInfo/ActiveAppInfo. Библиотеки и
helper остаются пакетными, исполняемый файл копируется с reflink при возможности.
Пакетные файлы не изменяются; proprietary-файлы в Git не добавляются.

Установка/обновление:

```sh
python ~/dotfiles/scripts/maintenance/install-wispr-context.py
systemctl --user restart wispr-flow.service
```

Делать после окончания диктовки. Неизвестная версия не патчируется вслепую.
При обновлении пакетного app.asar wrapper автоматически использует оригинальный
пакет до повторной установки патча. Для отката:

```sh
mv ~/.local/lib/wispr-context-runtime/manifest.json ~/.local/lib/wispr-context-runtime/manifest.disabled.json
systemctl --user restart wispr-flow.service
```

Диагностика текущего приложения: `wispr-context --json`. В ответе нет заголовка
окна и текста. Проверка метаданных не доказывает качество адаптации диктовки.

## Soniox

Для Linux подготовлен локальный клиент API; это не официальный desktop-клиент
Soniox. Зависимость `websocket-client==1.9.0` находится в отдельном venv.

- `sx` в Otter или `soniox` — окно настройки, последний ответ и тестовые фразы.
- Win+Alt+S — начать / остановить запись, находясь в целевом поле.
- `soniox toggle` — то же из команды; `soniox stop` — остановить запись.
- Во время записи не использовать одновременно бинд Wispr.
- Запись ограничена пятью минутами; при блокировке через обычный locker отменяется.
- Распознанный текст копируется. Если фокус остался в том же окне, вставляется
  Ctrl+V, а для терминала Ctrl+Shift+V. Enter автоматически не нажимается.
- Если окно сменилось, автоматической вставки нет: ответ остаётся в буфере.
- Окно содержит кнопки остановки, отмены и копирования. Закрытие отменяет запись.

Микрофон открывается только после явного старта и наличия ключа. Аудио передаётся
в облачный Soniox, локальная аудиозапись не сохраняется. Последний текст и времена
сохраняются в `~/.local/state/soniox/last.json` с правами 600; предыдущий результат
заменяется. Контекст Soniox: ru/en, предметная область Linux RE, словарь терминов.
Тексты окон и переписок в запрос Soniox не добавляются.

### Ключ

1. Открыть https://console.soniox.com/ и зарегистрироваться.
2. Проект → API Keys → Create API key. Достаточно Speech-to-text, real-time.
3. Вставить ключ в поле окна `sx` и нажать «Сохранить ключ».

Ключ находится только в `~/.config/soniox/api-key` (600), не передаётся через
аргументы команд и не попадает в Git. API-оплата отличается от подписки приложения;
пробный баланс и цену смотреть в Console. Без ключа/баланса реальная расшифровка
не проверена. Установка окружения при повторном развёртывании: `soniox-install`.

### Сравнение

В `sx` есть шесть фраз с Ghidra, ptrace, pwndbg, ELF, GOT/PLT и другими терминами.
Прочитать каждую по очереди в Wispr и Soniox одним микрофоном, в одной комнате.
Повторить два раза, чередуя порядок сервисов. Словарь Wispr желательно настроить
аналогично списку TERMS в `scripts/local-bin/soniox`.

Вставить любой полученный текст в поле `sx`, выбрать исходную фразу и нажать
«Оценить». WER показывает вставки/удаления/замены слов; меньше — лучше. Регистр
и пунктуация не учитываются, дефисы сохраняются. Счётчик терминов — приблизительный
поиск написаний, а не оценка смысла. Для Soniox выводится задержка после остановки;
это не скорость самого сервера, а измерение всего пути через сеть и клиент.
Задержку Wispr пока нужно измерить отдельно; автоматической оценки его скорости нет.

Проверено без API-ключа: интерфейс, ключ в тестовой папке, Clipboard, оценка фраз,
формирование PCM/config, финальные/промежуточные токены и завершение потока на
подставном транспорте. Запись с настоящим Soniox и сравнение точности ещё впереди.
