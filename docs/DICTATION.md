# Wispr Flow: контекст приложений

## Основной диктовщик · 28 октября 2026

Для повседневной работы оставлен Wispr Flow. Локальные сравнения сохранены,
их службы остановлены и глобальные бинды убраны. Их можно открыть вручную
через `vc`/`ha`; `wh` явно обозначен как локальный тестовый вариант.

- **Win+Alt+S** — начать / закончить запись Wispr (native action `popo`).
- **Win+Ctrl, удерживать** — прежний режим push-to-talk (`ptt`).
- **Esc** — отмена Wispr.
- `wf` в Otter — открыть Wispr через управляемую службу.

Выбраны `selectedLanguages=[ru,en]` вместо `[en,be]`, системный микрофон
`overrideAudioDeviceId=default` (при настройке это fifine Microphone Mono).
Команда нажатия Enter выключена, автоматический дополнительный Polish выключен.
В личный словарь через штатный интерфейс добавлен 51 термин: общий
`configs/dictation-compare/terms.txt` плюс `main`. Все записи проверены в базе;
исходные шесть записей сохранены. Копию БД напрямую для импорта не редактировали.

Win+Ctrl+Space убран из Wispr: он конфликтовал с переключением layout Awesome.
Временные Win+Alt+S Handy и Win+Ctrl+Alt+S Medium сняты с WM. Собственные
бинды Wispr не нужно одновременно перехватывать в Awesome/sxhkd.

Запуск GUI через wrapper сначала поднимает `wispr-flow.service`, дожидается её
single-instance lock, затем открывает окно. Поэтому повторное открытие не
оставляет основной процесс вне службы. Сохранены software rendering, контекстный
патч, guard с ограничением перезапусков и пауза на lock screen. Окно hub получает
собственное floating-правило; оверлеи Status/Scratchpad этим правилом не затронуты.

Личная резервная копия перед настройкой — `~/.local/state/wispr-tuning/`:
полный config и согласованная SQLite backup. Они содержат личные данные и не
попадают в Git. Словарь может синхронизироваться с аккаунтом Wispr; локальный
backup не является автоматическим откатом облачного словаря.

Проверено: сохранение настроек после перезапуска, 51/51 RE-терминов, один
MainPID под службой, helper, повторное открытие без смены MainPID, текущий
системный микрофон. Качество и фактическую задержку диктовки после этих правок
нужно проверить голосом пользователя. Гарантии «всегда до 3 секунд» нет.

## Облачные альтернативы · проверено 28 октября 2026

Подтверждённого победителя по русскому + RE-лексике без голосового A/B-теста нет.
С учётом Linux и требования бесплатности первым кандидатом остаётся OpenWhispr.

| Продукт | Бесплатное облако | Linux / практический вывод |
|---|---|---|
| Wispr Flow | Ограниченный Free; текущая документация описывает замедление после desktop allowance 2000 слов/неделю и блокировку при hard cap | Установлен сторонний Linux-порт, уже настроен под эту систему |
| OpenWhispr Cloud | 2000 слов/неделю; свой API-ключ не делает услуги провайдера бесплатными | Linux официально доступен, custom dictionary; первый кандидат для сравнения |
| Aqua Voice | 1000 бесплатных слов для старта, затем платные планы | Официальная платформа Linux не заявлена; Deep Context/код интересны, но это не готовая бесплатная замена на Awesome |
| Superwhisper | Бесплатны локальные модели; cloud/AI — Pro, стартовый доступ 3000 слов | Официальный Linux release channel есть, README всё ещё называет сборку preview для Omarchy; Awesome/X11 не проверен |
| Blip AI | 2000 слов в месяц | Есть Linux; бесплатная квота меньше Wispr/OpenWhispr, преимущества на твоём голосе не измерены |

Ни одна новая программа из этой таблицы не устанавливалась, платные планы не
включались. Заявления производителей о скорости не заменяют замера полной
цепочки «остановка записи → вставка» на этой машине.

## Wispr: контекст приложений

В установленной сборке `wispr-flow-appimage 1.0.4+wispr1.6.957-1` пустой
ответ helper и Linux-идентификаторы приложений мешали классификации контекста.
`wispr-context` читает только X11-метаданные активного окна: WM_CLASS, заголовок
и PID. Для терминала проверяет имена исполняемых файлов дочерних процессов.
Содержимое переписок, буфер обмена и вывод терминала эта добавка не читает.

- AyuGram/Telegram/64Gram → Telegram из каталога Wispr.
- ChatGPT Desktop и Claude Desktop → их известные идентификаторы.
- Codex/Claude/Gemini/Aider/OpenCode в терминале → `codingCliAgent`.
- В браузере распознаются только явные окончания заголовка ChatGPT, Claude,
  Gemini, NotebookLM. Это эвристика, URL не читается и не выдумывается.
- Полноценное чтение текстового поля, истории чата и страницы не добавлено.
  Настройка стиля и серверная обработка по-прежнему зависят от самого Wispr.

Создана отдельная копия runtime в `~/.local/lib/wispr-context-runtime`.
Патчируются только два места получения AppInfo/ActiveAppInfo. Библиотеки и
helper остаются пакетными, исполняемый файл копируется с reflink при возможности.
Пакетные файлы не изменяются; proprietary-файлы в Git не добавляются.

Установка/обновление:

```sh
python ~/dotfiles/scripts/maintenance/install-wispr-context.py
systemctl --user restart wispr-flow.service
```

Делать после окончания диктовки. Неизвестная версия не патчируется вслепую.
При обновлении пакетного app.asar wrapper автоматически использует оригинальный
пакет до повторной установки патча. Для отката:

```sh
mv ~/.local/lib/wispr-context-runtime/manifest.json ~/.local/lib/wispr-context-runtime/manifest.disabled.json
systemctl --user restart wispr-flow.service
```

Диагностика текущего приложения: `wispr-context --json`. В ответе нет заголовка
окна и текста. Проверка метаданных не доказывает качество адаптации диктовки.


Для следующих альтернатив диктовки использовать только бесплатное распознавание
без обязательного платного API. Новые варианты сначала согласовать с пользователем.
