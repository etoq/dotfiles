# TRIM и запуск thinkfan

Применено пользователем 19 октября 2026 для ThinkPad P50 eto. Резервная
копия: /var/backups/storage-and-boot-20261019-130420. После этого выполнена
обычная перезагрузка в Linux LTS 6.18.57-1-lts.

## Настройка

- TRIM раз в неделю штатным fstrim.timer, только для Btrfs на `/`.
- Корень получает allow-discards в параметре cryptdevice для GRUB и
  существующих systemd-boot entries с тем же зашифрованным устройством.
- Для всех подтомов системного Btrfs в fstab добавляется nodiscard, чтобы
  не совмещать периодический TRIM с постоянным discard. Ручной fstrim
  работает независимо от nodiscard.
- crypttab, LUKS-заголовки и `/vms` не меняются. Ни один ключ не извлекается.
- Фиксированные 5 секунд перед thinkfan заменяются ожиданием готовности
  настроенных датчиков по именам hwmon и интерфейса вентилятора. Проверка
  ограничена 10 секундами; после тайм-аута окончательная проверка остаётся
  за thinkfan, как и после прежнего фиксированного ожидания. Пороги, уровни
  и службы сна thinkfan не меняются, работающий вентилятор не перезапускается.

TRIM через LUKS позволяет увидеть расположение свободных блоков, но не
расшифровывает содержимое файлов. Периодичность не устраняет эту особенность.
Описание: [dm-crypt](https://www.kernel.org/doc/html/latest/admin-guide/device-mapper/dm-crypt.html),
[Btrfs TRIM](https://btrfs.readthedocs.io/en/latest/Trim.html).

## Применение

```bash
sudo python ~/dotfiles/scripts/maintenance/finish-storage-and-boot.py --apply
```

Скрипт сначала проверяет модель машины, UUID корня, путь шифрованного
устройства, поддержку discard накопителем, механизм encrypt и состояние
thinkfan. Проверяет оба ядра, модули NVIDIA и initramfs существующим
verify-kernel-stack. При неизвестных настройках останавливается.

Перед правками сохраняет затрагиваемые файлы и собственную копию в
root-only `/var/backups/storage-and-boot-ДАТА-ВРЕМЯ`. Проверяет временный
grub.cfg через grub-script-check до замены рабочего; при ошибке возвращает
сохранённые файлы. В резерв включён grub-btrfs.cfg, который побочно
перегенерируется при grub-mkconfig. Команда отката печатается в конце.

Скрипт не запускает TRIM, не обновляет активное LUKS-отображение, не
перезапускает thinkfan и не перезагружает ноутбук. Таймер включается для
следующей загрузки; новые параметры шифрования и fstab начинают действовать
после обычной перезагрузки. Выбирать Linux LTS с текущей NVIDIA 580.

После загрузки подтверждено: cryptroot пропускает discard (512 B / 2 TiB),
cryptvms по-прежнему нет (0 B / 0 B); fstab содержит nodiscard, в действующих
опциях Btrfs нет discard/async, счётчики отправленных bitmap/extent discard
равны нулю на момент проверки. fstrim.timer enabled/active, следующий запуск
26 октября; fstrim.service ограничен командой fstrim --verbose /.
Первый реальный запуск fstrim ещё не выполнялся, его журнал пуст.
Thinkfan прошёл проверку датчиков и запустился за 367 мс вместо 5.097 с,
управление уровнями вентилятора работает. Сбойных служб нет.

## Проверки подготовки

Восемь тестов проверяют изменения параметров загрузки и fstab, сохранение
посторонних параметров и `/vms`, повторный запуск, поиск датчика после
перенумерации hwmon и ограниченное ожидание недоступных датчиков.
Кандидаты GRUB, fstab и systemd-boot entry построены из текущих файлов;
повторное преобразование не вносит изменений. Чтение всех настроенных
датчиков и интерфейса вентилятора на работающей машине успешно.

Control Deck показывает `Last Backup: DD:MM:YYYY`; подсказок у даты и VM нет.
Размеры панели не менялись. GTK-проверка на виртуальном экране подтвердила
отсутствие подсказок; побочный конфликт адреса AT-SPI устранён перезапуском
службы доступности. Документный портал и wispr-a11y-guard снова работают,
сбойных пользовательских служб после восстановления нет.
