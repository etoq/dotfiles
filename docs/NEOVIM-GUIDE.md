# Твой Neovim: проект, код и отладка

Win+F2 — большой справочник на одном экране. Внутри Neovim: `:NvimGuide` или
**Пробел ug** открывает этот документ. Пробел — Leader: например, «Пробел ff»
означает нажать пробел, затем f и ещё раз f, в обычном режиме.
Обычные F-клавиши работают внутри Neovim; Win+F-клавиши открывают справочники Awesome.

## 1. Открыть проект

Из терминала перейти в корень проекта и запустить `nvim .`. Корень — папка,
где лежат `.git`, `pyproject.toml`, `Cargo.toml`, `Makefile` или `CMakeLists.txt`.
Так поиск по проекту, терминал и сборка начинают с понятного каталога.
При необходимости внутри редактора: `:pwd` показывает каталог, `:cd ПУТЬ` меняет его.

- Пробел tt — показать/скрыть дерево, Пробел tf — перейти в него.
- Пробел ff — найти файл по имени. Пробел ft — найти текст в проекте через rg.
- В Telescope печатать запрос, выбирать стрелками/Ctrl+N/Ctrl+P, Enter — открыть,
  Esc при необходимости дважды — закрыть. Ctrl+Q отправляет результаты в quickfix;
  затем `:copen`, `:cnext`, `:cprev`.
- В дереве Enter — открыть файл, Ctrl+V — вертикальным сплитом, a — создать,
  r — переименовать, x/c/p — вырезать/копировать/вставить, H — скрытые файлы,
  R — обновить, g? — полная справка дерева. Удаление через d требует внимания.

## 2. Режимы: почему текст иногда не вводится

После Esc включён normal — команды и навигация. i включает ввод перед курсором,
a — после него, o — новую строку снизу. Esc возвращает normal. v выделяет символы,
V — строки, Ctrl+V — прямоугольный блок. Двоеточие открывает командную строку.

`h/j/k/l` — влево/вниз/вверх/вправо; `w/b/e` — по словам; `0/^/$` — начало,
первый непробельный символ и конец строки. `gg/G` — начало/конец файла, `:42` —
строка 42. Относительные номера помогают: `8j` на восемь строк вниз, `3w` на три слова.
`%` — парная скобка. Ctrl+D/Ctrl+U — полэкрана вниз/вверх.

## 3. Править код

- Ctrl+S сохраняет файл в normal и insert. `:wa` сохраняет все изменённые файлы.
- u отменяет, Ctrl+R возвращает отменённое, точка повторяет последнюю правку.
- dd вырезает строку, yy копирует, p вставляет после/ниже, P — перед/выше.
- ciw заменяет слово под курсором, diw удаляет, yiw копирует.
- `ci"` заменяет текст внутри кавычек, `ci(` — внутри скобок, `ca(` — вместе со скобками.
- gcc комментирует строку; выделение → gc комментирует несколько строк.
- `>>/<<` меняет отступ строки, `==` выравнивает текущую строку, `gg=G` — весь файл.
- В этой конфигурации Ctrl+A **копирует весь файл в буфер ОС**. Системный буфер
  общий с Neovim, поэтому удаление также меняет текущий регистр. `"0p` вставляет
  последний скопированный через yank текст, даже после удаления другого текста.
- Ctrl+Q — обычное `:q`: несохранённые изменения не выбрасываются автоматически.

`/строка` ищет по файлу, n/N — дальше/назад, `*` ищет слово под курсором.
`:noh` снимает подсветку. `:%s/old/new/gc` заменяет по всему файлу с подтверждением:
y — заменить, n — пропустить, q — закончить. Это текстовая замена, она не знает
структуру программы. Для переименования символа используй LSP.

## 4. Файлы, окна и вкладки

**Буфер** — открытый файл; **окно/сплит** — место его отображения; **вкладка Neovim** —
отдельная раскладка окон. Это не то же самое, что вкладки Kitty.

Tab/Shift+Tab переключают буферы, Пробел fb показывает список. Ctrl+L закрывает
остальные буферы — это твой нестандартный бинд. `:vsplit` делит окно справа,
`:split` снизу. Ctrl+W, затем h/j/k/l переходит к соседнему окну; Ctrl+W = выравнивает
размеры; Ctrl+W o оставляет одно окно. Пробел wc закрывает текущий сплит.
Пробел tn — новая вкладка, Пробел j/k — следующая/предыдущая, Пробел tr — имя,
Пробел tw — закрыть вкладку; если она последняя, выполняется выход.

## 5. Интеллектуальные действия с кодом

LSP — отдельный языковой сервер: он понимает определения, типы и ссылки на символы.
Для C/C++ у тебя установлен clangd, для Python — pyright. Конфиги Ruff и TypeScript
также присутствуют, но на момент проверки их исполняемые файлы не найдены.
Rust Analyzer не установлен и не настроен. Не все языки уже обеспечены одинаково.
Новых серверов в рамках этой задачи не скачивали.

- gd — определение, gD — объявление, gi — реализация; Ctrl+O возвращает назад.
- Пробел ld/lD — те же определение/объявление.
- Пробел lk — документация символа, Пробел lr — все места использования.
- Пробел ln — **переименовать символ через LSP**; связанные места меняет сервер.
- Пробел rn — старый бинд **переименования самого файла**, это другое действие.
  Для файлов с пробелами в пути лучше использовать r в дереве.
- Пробел la — действия/исправления, которые предлагает сервер.
- Пробел lf — форматирование, только если подключённый сервер это умеет.
  Если форматировщика нет, будет понятное уведомление; настройка не скачивает его.
- [d/]d — предыдущая/следующая диагностика, Пробел e — сообщение под курсором,
  Пробел lq — список ошибок файла.

Python-диагностика pyright больше не подавляется настройкой `ignore = { '*' }`:
включена базовая проверка открытых файлов. Pyright не заменяет отдельный форматировщик.
Для проекта Python желательно сначала активировать его виртуальное окружение в
терминале и оттуда запускать Neovim. В C/C++ clangd может требоваться
`compile_commands.json` со флагами сборки и путями заголовков.

В insert Ctrl+Space открывает дополнение, Tab/Shift+Tab выбирают вариант, Enter
принимает, Ctrl+E закрывает. Часть подсказок идёт из буферов/путей: наличие меню
само по себе не доказывает, что LSP подключён. `:checkhealth vim.lsp` показывает
состояние, `:Mason` — установленные инструменты. Если сервер не подключён,
проверь тип файла `:set filetype?` и наличие нужного инструмента.

## 6. Запуск, сборка и Git

F4 запускает текущий C/Python-файл через Code Runner; F5 закрывает его окно.
Это удобство для небольших одиночных файлов, не универсальная сборочная система:
для проектов используй их штатные команды. F4 действительно выполняет код.

Пробел s открывает плавающий терминал. Там можно запускать `make`, `cmake --build build`,
`cargo build`, `cargo test`, `python -m pytest`, `git status`, `git diff`.
Esc выводит из ввода терминала, i возвращает ввод. Ctrl+C во время ввода останавливает
обычную запущенную команду. Сборка `:make` использует текущий `makeprg`; ошибки
открываются через `:copen`, `:cnext`, `:cprev`.

Пробел gs показывает изменённые файлы, Пробел gc — историю коммитов, Пробел gb —
ветки через Telescope. Просмотр коммитов не создаёт коммит. Для осознанного
добавления/коммита/отправки используй Git в терминале или существующий lazygit.

## 7. Что за отладчик и чем отличается от pwndbg

`nvim-dap` — клиент Debug Adapter Protocol. Он управляет внешним отладчиком,
а `nvim-dap-ui` показывает исходник, точки, переменные, watch-выражения, стек
вызовов и REPL. Установленные адаптеры:

| Язык | Что реально отлаживает |
| --- | --- |
| Python | debugpy, запущенный из своего окружения Mason |
| C, C++, Rust | CodeLLDB / LLDB; нужно выбрать собранный исполняемый файл |

Исправлены пустой путь CodeLLDB (Mason настраивался слишком поздно) и запуск
debugpy системным Python, в котором этот модуль отсутствовал.
Адаптер Python живёт в окружении Mason, а интерпретатор **самой программы**
может быть из твоего проекта/активированного venv — эти две роли различаются.

Pwndbg — расширение GDB/LLDB с инструментами анализа бинарников: память,
регистры, стек, heap, карты памяти и другие команды. Текущая связка CodeLLDB
**не загружает pwndbg**, и команды `vmmap`/`telescope` не появляются в DAP REPL
автоматически. Для своего исходного кода удобно DAP; для привычного анализа
бинарника можно открыть `:terminal gdb ./demo` — твой `~/.gdbinit` загружает pwndbg.
Этот терминал и панели DAP — независимые сеансы отладки.

## 8. Пример Python

Создать собственный `demo.py`:

```python
def twice(value):
    result = value * 2
    return result

answer = twice(21)
print(answer)
```

Сохранить Ctrl+S. На строке `result = value * 2` поставить точку F9. F12 → выбрать
запуск файла, например Launch file. При остановке смотреть переменные и стек;
выражение `value` можно посмотреть через Пробел de. F10 делает шаг, F11 входит
в функцию, Shift+F11 выходит из неё. F12 продолжает, Пробел dt завершает сеанс.
Программа при этом реально выполняется.

Если Python-файл запускается как модуль пакета с относительными импортами,
нужна конфигурация запуска модуля/проекта, а не просто Launch file. Базовый
набор — не готовые launch-настройки для любого проекта.

## 9. Пример C/C++/Rust

Для C сначала собрать свой пример с символами, в терминале из корня проекта:

```sh
gcc -g -O0 main.c -o demo
```

Открыть исходник, F9 на исполняемой строке, F12 → LLDB: Launch → выбрать полный
путь к `demo`, а не `main.c`. Для C++ аналогично `g++ -g -O0 main.cpp -o demo`.
Для Rust: `cargo build`, затем выбрать `target/debug/ИМЯ_ПРОГРАММЫ`.
Оптимизированная сборка может пропускать строки и скрывать переменные.
Запуск F4 для C не добавляет отладочные символы — для DAP используй сборку выше.

Пространство/панели DAP:

| Клавиши | Действие |
| --- | --- |
| F9 | Точка останова |
| F12 | Запуск / продолжить |
| F10 / F11 / Shift+F11 | Шаг поверх / внутрь / до возврата |
| Пробел dc / db | До курсора / условная точка |
| Пробел de | Значение выражения под курсором или в выделении |
| Пробел du / dr | Показать панели / REPL |
| Пробел dt | Завершить отладку |

Панели открываются автоматически при начале сеанса. Если закрыл их вручную,
вернуть через Пробел du. Не пытайся одновременно управлять одним процессом из
GDB и LLDB. Отладку неизвестного ВПО выполнять в своей лабораторной ВМ;
редактор на рабочем хосте остаётся рабочим редактором.

## 10. HEX и дополнительные возможности

Пробел h включает/выключает HEX-режим. Это **редактор**, а не гарантированно
безопасный просмотрщик: запись `:w` может изменить исходный бинарник.
Для просмотра открывай `nvim -R ФАЙЛ` и не используй принудительную запись;
для патчей сначала сделай отдельную копию.

Compiler Explorer установлен отдельно, но его онлайн-компиляция может передавать
исходный код внешнему сервису. В базовый цикл работы и автоматическую проверку
он не включён. Win+F2 не выполняет ничего из перечисленного — это только справка.

Проверено на этой станции: запуск Neovim без ошибок; переход к определению,
запрос переименования символа и диагностика в C/Python; остановка на точке,
шаг и чтение переменных в CodeLLDB/debugpy на собственных маленьких программах.
Отдельные проекты C++/Rust и их зависимости в этой проверке не запускались.

Источники: локальные `configs/nvim/`, реально установленные плагины и проверки
конфигурации; [nvim-dap](https://github.com/mfussenegger/nvim-dap),
[dap-python](https://github.com/mfussenegger/nvim-dap-python),
[Pwndbg](https://pwndbg.re/stable/).
